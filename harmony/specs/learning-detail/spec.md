# Feature Specification: 学习详情深链

**Created**: 2026-10-27  
**Status**: Draft  
**Input**: User description: "T05 · 学习详情深链：补齐课程详情聚合、通知正文、资料下载/预览、手动 DDL 持久化。"

## Overview

学习模块目前只能看到课程、作业、通知、资料的扁平列表，进入课程后只有课号/教师/学期三项基本信息；通知正文依赖同步时内联的数据；资料详情的下载按钮没有行为；手动添加的 DDL 只存在于内存，重启即丢失，且首页看不到。

本特性把「列表」升级为「可下钻的学习工作台」：课程详情聚合该课程下的作业、通知与资料；通知详情可靠地展示正文；资料可预览与下载到本地；手动 DDL 跨重启保留，并在学习页与首页共享同一份数据。演示模式下所有详情仍可用，但不得发起任何网络请求。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 课程详情聚合三类数据 (Priority: P1)

学生在学习页的课程列表点开一门课，希望在同一个页面里看到这门课的全部作业、通知和资料，并能继续点进任意一条查看详情，而不是回到四个标签之间来回切换。

**Why this priority**: 课程是学习模块的天然入口，聚合页决定了下钻效率；没有它，通知/资料详情缺少稳定入口。

**Independent Test**: 在学习页选择任一课程进入详情，确认三个分组都出现；分别点击一条作业、一条通知、一条资料，都能进入对应详情并正确返回。

**Acceptance Scenarios**:

1. **Given** 学习页已加载某课程的作业、通知、资料，**When** 打开该课程详情，**Then** 页面显示该课程基本信息、三类分组标题及各自数量，且只包含属于该课程的条目。
2. **Given** 课程详情已展示三类分组，**When** 点击某条作业，**Then** 进入作业详情；点击某条通知，**Then** 进入通知详情；点击某条资料，**Then** 进入资料详情。
3. **Given** 某课程没有通知或没有资料，**When** 打开课程详情，**Then** 对应分组显示明确的空态文案，其余分组正常展示。
4. **Given** 学习页尚未加载该课程的作业/通知/资料（例如刚冷启动直接从外部入口进入），**When** 打开课程详情，**Then** 系统自动补拉一次该课程的三类数据；补拉失败时保留基本信息并给出可读提示，不出现无限加载。
5. **Given** 目标课程已不存在于当前学期列表，**When** 以该课程标识打开详情，**Then** 显示「课程不存在或已不可用」的可读空态，不崩溃。

### User Story 2 - 通知正文可见 (Priority: P1)

学生点开一条课程通知，希望直接读到完整正文（而不是只有标题或空白），并能看到发布人、发布时间等上下文。

**Why this priority**: 通知是教师传达要求的唯一渠道，正文不可见等于通知功能失效。

**Independent Test**: 在真实模式点开一条有正文的通知，正文完整可见；点开一条正文为空的通知，显示明确空态；在演示模式点开样例通知，正文可见且没有网络请求。

**Acceptance Scenarios**:

1. **Given** 同步时已取得通知正文，**When** 打开通知详情，**Then** 正文立即展示，标题、课程、发布人、发布时间同时可见。
2. **Given** 同步结果中该通知正文为空，**When** 打开通知详情，**Then** 系统按所属课程重新拉取一次通知列表，并按通知标识匹配正文；匹配成功则展示，仍为空则显示「暂无正文」空态。
3. **Given** 补拉失败或会话失效，**When** 打开通知详情，**Then** 页面保留标题与元信息，正文区域显示可读的失败提示与重试入口。
4. **Given** 打开通知详情，**When** 页面渲染完成，**Then** 不修改通知的已读/未读状态（本特性只读）。

---

### User Story 3 - 资料下载与预览 (Priority: P1)

学生打开一份课程资料，希望先在应用内预览内容；需要留存时把文件下载到本地，之后还能再次打开。

**Why this priority**: 资料详情当前只有元信息，下载按钮无行为，是学习链路最明显的断点。

**Independent Test**: 打开一份资料，点击预览能在应用内看到内容；点击下载后出现成功提示并可再次打开已下载文件；断网时下载给出可读失败提示且不影响已下载文件。

**Acceptance Scenarios**:

1. **Given** 已登录且资料可用，**When** 打开资料详情，**Then** 展示标题、课程、类型、大小、上传时间与说明。
2. **Given** 资料详情已打开，**When** 点击预览，**Then** 在应用内浏览器中加载该资料的预览页，并携带当前登录会话；加载中显示进度，失败显示可读提示。
3. **Given** 资料详情已打开，**When** 点击下载，**Then** 文件下载到应用私有目录，按钮进入下载中状态，成功后提示保存位置并提供再次打开入口。
4. **Given** 同一资料已下载过，**When** 再次打开详情，**Then** 显示「已下载」状态，可直接打开，无需重复下载。
5. **Given** 下载过程中网络中断或会话失效，**When** 下载失败，**Then** 显示可读错误与重试入口，不产生半截文件，已有文件不受影响。
6. **Given** 处于演示模式，**When** 点击预览或下载，**Then** 不发起网络请求，给出「演示模式不可用」的明确提示。

### User Story 4 - 手动 DDL 持久化并共享 (Priority: P1)

学生把课程要求或个人待办记为手动 DDL，希望重启应用后仍在，并且在学习页和首页看到同一份数据；不再需要时能删除。

**Why this priority**: 当前手动 DDL 只存在内存，重启即丢失，是数据可靠性问题；同时首页与学习页展示不一致。

**Independent Test**: 新增一条手动 DDL，完全退出并重启应用，学习页与首页仍能看到；删除后两处同时消失；通过 AI 新增的 DDL 也出现在两处。

**Acceptance Scenarios**:

1. **Given** 在学习页打开展开的手动 DDL 表单，**When** 填写标题、日期、时间（可选课程与备注）并保存，**Then** 新条目出现在作业列表与首页最近 DDL 中。
2. **Given** 标题为空、日期或时间格式不合法，**When** 保存，**Then** 阻止保存并给出对应字段的可读提示。
3. **Given** 已存在手动 DDL，**When** 完全退出并重新启动应用，**Then** 所有手动 DDL 仍在，顺序按截止时间升序。
4. **Given** 已存在手动 DDL，**When** 在学习页删除并确认，**Then** 该条目从学习页与首页同时消失，重启后不再出现。
5. **Given** 通过 AI 助手新增或删除了一条手动 DDL，**When** 返回学习页与首页，**Then** 展示与 AI 操作结果一致，无需手动刷新应用。
6. **Given** 手动 DDL 与老师布置的作业同时存在，**When** 查看作业标签，**Then** 两类条目合并展示且可区分来源；已提交/已批改的作业不混入该列表。

---

### User Story 5 - 演示模式详情可用且零请求 (Priority: P2)

未登录或开启演示模式的用户/评审者，希望完整走通「课程 → 通知 → 资料」的下钻链路，用于演示与验收，同时确保不产生任何真实网络流量。

**Why this priority**: 演示模式是本项目的固定验收场景；当前演示模式下详情字段为空、资料列表为空，链路是断的。

**Independent Test**: 开启演示模式，从学习页依次进入课程、通知、资料详情，全部有内容；抓取日志确认无学习相关网络请求。

**Acceptance Scenarios**:

1. **Given** 处于演示模式，**When** 打开学习页，**Then** 展示内置的课程、作业、通知、资料样例，不发起网络请求。
2. **Given** 处于演示模式，**When** 打开课程详情，**Then** 三类分组均有样例数据且可下钻。
3. **Given** 处于演示模式，**When** 打开通知详情与资料详情，**Then** 正文与元信息可见；预览/下载按钮给出演示态提示且不发请求。
4. **Given** 处于演示模式，**When** 新增或删除手动 DDL，**Then** 操作即时生效并在本地持久化，重启后仍在。

---

### Edge Cases

- 课程详情补拉与学习页同步同时进行时，以最后一次成功结果为准，不重复叠加条目。
- 通知正文可能是富文本，展示时不得执行脚本、不得加载外部资源；纯文本与富文本都要可读。
- 资料文件名为空或缺少扩展名时，展示回退为「文件」，下载仍使用服务端返回的文件标识。
- 下载目录不可写或磁盘空间不足时，提示可读错误，不覆盖已有同名文件。
- 手动 DDL 的日期/时间只做格式校验，允许已过期时间；过期项仍展示但需有视觉区分。
- 同一手动 DDL 被 AI 与页面同时删除时，第二次删除按「已不存在」处理，不报错。
- 会话失效时，详情页的补拉/下载必须失败可读，不得长时间无反馈。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 课程详情 MUST 展示课程基本信息（名称、课号、教师、学期）与三个分组：作业、通知、资料。
- **FR-002**: 课程详情的三个分组 MUST 只包含属于该课程的条目，并显示各自数量。
- **FR-003**: 课程详情 MUST 支持从任一作业、通知、资料条目进入对应详情页，并可返回课程详情。
- **FR-004**: 课程详情 MUST 在本地缺少该课程三类数据时自动补拉一次；补拉失败时 MUST 保留基本信息并显示可读提示。
- **FR-005**: 课程详情 MUST 为每个空分组显示独立空态，不得用整页空态掩盖其它分组。
- **FR-006**: 任一详情页 MUST 能以条目标识定位内容；本地列表未命中时 MUST 尝试重新拉取并匹配，未命中才显示空态。
- **FR-007**: 通知详情 MUST 展示标题、所属课程、发布人、发布时间与正文。
- **FR-008**: 通知正文 MUST 优先使用同步时已取得的内容；正文为空时 MUST 按所属课程补拉一次并按通知标识匹配。
- **FR-009**: 通知详情 MUST 在补拉失败时保留元信息，并在正文区域提供失败提示与重试入口。
- **FR-010**: 通知详情 MUST 为只读，不得回写已读状态。
- **FR-011**: 资料详情 MUST 展示标题、课程、类型、大小、上传时间与说明。
- **FR-012**: 资料详情 MUST 提供应用内预览，且预览请求 MUST 携带当前登录会话。
- **FR-013**: 资料详情 MUST 提供下载到应用私有目录的能力，并展示下载中、成功、失败三种状态。
- **FR-014**: 已下载的资料 MUST 可再次打开，并在详情页显示「已下载」状态；重新下载 MUST 不产生半截文件。
- **FR-015**: 下载失败 MUST 给出可读错误与重试入口。
- **FR-016**: 手动 DDL MUST 持久化到本地，并在应用重启后恢复。
- **FR-017**: 学习页 MUST 支持新增手动 DDL，至少校验标题非空、日期与时间格式合法。
- **FR-018**: 学习页 MUST 支持删除手动 DDL，删除前 MUST 有确认。
- **FR-019**: 学习页与首页 MUST 共享同一份手动 DDL 数据；任一处变更后另一处 MUST 在下次展示时一致。
- **FR-020**: AI 助手写入或删除的手动 DDL MUST 与页面展示使用同一份数据，不得形成两套。
- **FR-021**: 作业标签 MUST 合并展示未提交的远程作业与手动 DDL，按截止时间升序，并可从视觉上区分来源。
- **FR-022**: 演示模式 MUST 提供课程、作业、通知、资料四类本地样例，且课程详情三类均可下钻。
- **FR-023**: 演示模式下的任何详情操作 MUST 不发起网络请求；预览/下载 MUST 给出演示态提示。
- **FR-024**: 所有新增可见文案 MUST 支持中英文切换，不得在页面层硬编码中文。

### Key Entities

- **课程**：一门本学期课程，含名称、课号、教师、学期；是作业/通知/资料的归属维度。
- **作业**：教师布置的任务，含标题、所属课程、截止时间、提交/批改状态、详情地址；本特性只读。
- **通知**：教师发布的公告，含标题、所属课程、发布人、发布时间、正文、已过期标记；本特性只读。
- **资料**：课程文件，含标题、所属课程、类型、大小、上传时间、说明、预览地址、下载地址；本特性只预览与下载。
- **手动 DDL**：学生自建的截止提醒，含标识、标题、日期、时间、可选课程名、可选备注、创建时间；与远程作业无数据关联，仅合并展示。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 从学习页进入任一课程详情，三个分组在 1 秒内完成首屏渲染（本地已有数据时），且分组计数与列表筛选结果 100% 一致。
- **SC-002**: 有正文的通知在真实模式下正文可见率达到 100%；正文确实为空时 100% 显示明确空态而非空白区域。
- **SC-003**: 已在应用内成功预览与下载的资料占可访问资料的比例不低于 95%（网络与会话正常时）；下载失败 100% 有可读提示与重试入口。
- **SC-004**: 手动 DDL 在新增/删除后重启应用，数据一致率为 100%；学习页与首页展示一致率为 100%。
- **SC-005**: 演示模式下学习相关网络请求数为 0，且课程→通知→资料三级下钻全部可达。
- **SC-006**: 从列表进入任一详情不超过 2 次点击，返回后保持原标签与滚动位置。

## Assumptions

- 真实数据依赖已登录且会话有效的校园网络环境；会话失效按可读失败处理，不在本特性内实现自动重登。
- 通知正文在同步阶段已随列表取得；补拉仅针对正文为空的条目，不新增「按条拉正文」的服务端契约。
- 资料预览使用服务端提供的预览页；下载保存到应用私有目录，不申请外部存储权限，也不做系统级分享。
- 手动 DDL 沿用既有本地数据格式与既有 AI 写入数据，不新增迁移步骤；不做重复日程、提醒推送与日历同步。
- 与 RN 的行为差异（有意改进）：RN 的课程/通知/资料详情只读本地快照，本特性在快照缺失时允许补拉；RN 页面新增的手动 DDL 不落盘，本特性修复为持久化。
- 作业提交、讨论区、文件上传不在本特性范围内。
- 课程详情分组不设条数截断；列表过长时由页面滚动承载。

## Open Questions

- 无未决问题。范围、正文获取策略、下载/预览方式、手动 DDL 范围与演示模式数据均已确认。
