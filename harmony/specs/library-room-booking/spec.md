# Feature Specification: 研读间预约（含取消与成员邀请）

**Created**: 2026-10-16
**Status**: Draft
**Input**: User description: "接入研读间预定"（经澄清：写操作范围 = 预约 + 取消；预约含**成员邀请**；spec 产物新建 `library-room-booking` 目录）。

## Overview

在既有"校园 → 场馆预约 → 研读间"只读能力（类型 → 近 5 天 → 资源（含开放时间/时长规则/占用）+ 我的预约）之上，补齐**预约**与**取消**写操作：用户选定日期与时段、邀请成员（按姓名/学号搜索），二次确认后提交预约；并可在"我的预约"中取消可取消的记录。会话沿用研读间子系统（cab）登录与两层恢复；演示模式下读写均不发起网络请求。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 预约研读间 (Priority: P1)

用户在研读间资源列表中选择某房间发起预约：选择日期（近 5 天）与时段（起止时间），系统按房间规则校验（开放时间、最短/最长时长、人数上下限、时段未被占用），随后弹出二次确认；确认后提交，成功时提示并刷新"我的预约"。

**Why this priority**: 预约是本次接入的核心新价值（把"只读查询 + 跳小程序下单"变为应用内可下单）。

**Independent Test**: 对某可预约房间选择合法时段并确认提交，可看到成功提示，且"我的预约"出现该记录。

**Acceptance Scenarios**:

1. **Given** 已登录、研读间会话有效、处于某类型某日的资源列表，**When** 选择某房间并填合法日期/时段后提交并确认，**Then** 提交成功并提示，"我的预约"刷新出现该记录
2. **Given** 时段不满足房间规则（超出开放时间/时长短于最短或长于最长/人数不符/时段已被占用），**When** 尝试提交，**Then** 阻止提交并给出可读原因
3. **Given** 提交所需会话/账号就绪，**When** 提交，**Then** 请求携带当前账号与所选设备等必要字段（对齐参考实现）
4. **Given** 演示模式（未登录或演示开关开启），**When** 尝试预约，**Then** 不发起网络请求，给出可读提示

---

### User Story 2 - 邀请成员 (Priority: P1)

用户在预约前可邀请其他成员：按姓名/学号关键词模糊搜索，选择结果加入成员列表（可移除）；系统据此与房间的人数上下限（minUser/maxUser）校验。

**Why this priority**: 多人研讨间存在最小人数下限，缺少成员邀请将无法预约此类房间。

**Independent Test**: 输入关键词可返回候选成员并加入/移除；人数不符时提交被阻止并给出可读原因。

**Acceptance Scenarios**:

1. **Given** 已登录且会话有效，**When** 输入姓名/学号关键词搜索，**Then** 返回候选成员列表（结果脱敏展示）
2. **Given** 已加入若干成员，**When** 与房间 minUser/maxUser 校验，**Then** 人数不足/超限时阻止提交并给出可读原因
3. **Given** 已加入成员，**When** 触发移除，**Then** 该成员从列表移除并重算人数

---

### User Story 3 - 取消预约 (Priority: P2)

用户在"我的预约"中对可取消的记录发起取消：二次确认后提交，成功时提示并刷新记录列表。

**Why this priority**: 与预约配套，避免用户必须去官方小程序才能取消。

**Independent Test**: 在"我的预约"点某记录"取消"，确认后见成功提示，且列表更新。

**Acceptance Scenarios**:

1. **Given** 已登录且"我的预约"存在可取消记录，**When** 点击取消并确认，**Then** 提交成功并提示，列表刷新
2. **Given** 记录不可取消（如已过期/已取消），**When** 查看该记录，**Then** 不提供"取消"操作（或以禁用态呈现）

---

### Edge Cases

- 会话（cab）失效 / 子系统会话过期时，应自动恢复（重新 cab 登录 + 账号校验）后重试；恢复失败展示可读错误与重试入口（读与写均适用）
- 研读间接口返回非 JSON 或业务码非 0（`code !== 0`）时，应转为可读错误而非崩溃
- 提交前若目标时段被他人占用（`usage` 与所选时段重叠），应阻止并提示"该时段已被占用"
- 日期范围仅"近 5 天"；时段须落在房间开放时间（openStart/openEnd）内
- 提交中应避免重复提交（按钮禁用/加载态）
- 演示模式（未登录或演示开关开启）下读写均不发起网络请求，写操作给出可读提示
- 成员搜索结果涉及他人信息，应脱敏展示
- 写操作与错误信息不得包含会话/凭据明文

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 必须在既有研读间资源页（类型 → 近 5 天 → 资源）基础上，为资源提供"预约"入口
- **FR-002**: 预约必须可选择日期（近 5 天）与时段（起止 HH:mm）
- **FR-003**: 时段必须按房间规则校验：不超出开放时间（openStart/openEnd）、时长在最短/最长（minMinute/maxMinute）内
- **FR-004**: 提交前必须校验所选时段与既有占用（usage）不重叠；重叠时阻止并给出可读原因
- **FR-005**: 必须支持邀请成员：按姓名/学号关键词模糊搜索、加入与移除；并按房间人数上下限（minUser/maxUser）校验
- **FR-006**: 提交前必须二次确认（展示房间、日期、时段、人数/成员）
- **FR-007**: 提交请求必须携带当前账号标识与所选设备等必要字段（对齐参考实现）
- **FR-008**: 预约成功后必须刷新"我的预约"并给出结果提示
- **FR-009**: 必须支持取消"我的预约"中可取消的记录（按记录标识提交；二次确认；成功后刷新）
- **FR-010**: cab 会话失效必须自动恢复并重试；恢复失败展示可读错误与"重试"入口
- **FR-011**: 演示模式必须使用内置示例数据；**读与写均不发起网络请求**
- **FR-012**: 接口异常（非 JSON / 业务码非 0 / 结构不符）必须转为可读错误，禁止崩溃或暴露原始异常文本
- **FR-013**: 提交中必须避免重复提交（禁用/加载态），防止重复下单
- **FR-014**: 写操作（预约/取消）相关日志与错误信息不得包含凭据明文
- **FR-015**: 卡片与列表布局必须遵循项目约定（全宽卡片配 `constraintSize` 防右缘溢出）；新增可见文案走 i18n（中/英成对）

### Key Entities *(include if feature involves data)*

- **研读间类型**：标识、名称、下属房间简述（标识、名称、最短预约时长）
- **研读间资源**：设备/房间标识与名称、所属类型、人数上下限、最短/最长时长、可取消时限、开放时间（起止）、占用区间列表（起止/标题/归属）
- **成员（搜索结果）**：账号标识、姓名、单位（脱敏展示）
- **预约记录**：标识（uuid）、房间/类型、日期与起止、成员、归属
- **预约时段**：日期 + 起止时间（HH:mm）
- **账号标识（cabAccNo）**：当前账号在研读间子系统的标识（会话校验后缓存）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对合法时段的研读间，在二次确认后**一次提交成功率 ≥ 90%**，且成功后"我的预约"立即可见该记录
- **SC-002**: 对可取消记录的取消，在二次确认后**一次提交成功率 ≥ 90%**，列表随之更新
- **SC-003**: 成员搜索在 3 秒内返回候选结果；人数不符时提交被阻止率 100%
- **SC-004**: 会话失效场景下，用户无需手动重新登录即可在自动恢复后完成读写（恢复成功率 ≥ 90%）
- **SC-005**: 演示模式下页面 100% 离线可用（零网络请求）
- **SC-006**: 接口异常或会话不可恢复时，100% 展示可读中文错误（无崩溃、无原始异常文本）
- **SC-007**: 规则校验（开放时间/时长/人数/占用）覆盖下，非法提交被阻止率 100%

## Assumptions

- 写接口对齐参考实现：预约 `POST …/ic-web/reserve`（body 含 `sysKind:1`、`appAccNo`（当前账号标识）、`memberKind:1`、`resvBeginTime`、`resvEndTime`、`resvKind:2`、`resvProperty:0`、`resvMember:[成员账号]`、`resvDev:[设备标识]`、`memo`、`captcha`、`addServices` 等）；取消 `POST …/ic-web/reserve/delete`（body `{uuid}`）。响应为 JSON，业务码 `code === 0` 视为成功
- 时间提交格式对齐参考实现（`YYYY-MM-DD HH:mm`）；确认框与时区按本机日期
- 会话沿用既有研读间子系统登录（cab 登录 + 账号校验）与两层恢复；写操作复用既有 `withCabRetry` 范式
- 成员搜索接口返回账号标识，用于预约 body 的 `resvMember`
- 日期范围仅"近 5 天"（与既有只读页一致）；不提供自定义日期或跨天预约
- 演示模式下写操作以提示代替真实提交（不发起请求）
- 既有只读浏览（类型/资源/我的预约）能力保留复用，不在本特性重做

## Open Questions

- `resvBeginTime`/`resvEndTime` 是否需包含秒（参考实现接受 `HH:mm` 或 `HH:mm:ss`；提交格式需与参考一致）
- 预约是否需要验证码（`captcha` 字段留空是否可提交）
- "我的预约"是否需要展示已过期/历史记录（当前按接口近 7 天返回）
