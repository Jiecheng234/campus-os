# Feature Specification: AI 治理（审计持久化 + 权限 UI）

**Created**: 2026-10-21  
**Status**: Draft  
**Input**: User description: "T04 · AI 治理：审计持久化 + 权限 UI。目标：让高风险写操作可审计、可授权、可关闭。范围：StorageKeys.ACTION_AUDIT 持久化；设置页查看/清空审计；AI 权限页按能力类别启停；AgentTools/AgentWriteTools 执行前检查权限；保留现有确认链。非目标：改变现有风险分级；新增工具。验收：审计跨重启保留；权限关闭后工具不可调用/返回可读拒绝；设置页可查看/清空；日志无敏感明文。"

## Overview

把 AI Agent 的工具调用治理从"会话内内存态"升级为"跨重启可追溯、可按能力授权、可一键关闭"。用户在设置页即可回看最近一次写操作是否被确认、成功还是失败，也可以清空记录；AI 权限页按能力类别逐项启停，关闭后对应工具不再下发给模型，即便模型强行点名也会被可读拒绝且不产生副作用。现有"预览 → 二次确认 → 执行 → 验证"链保持不变，仅在其前后增加"权限门禁"与"审计落盘"。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 跨重启回看 AI 操作记录 (Priority: P1)

用户在 AI 对话里让助手执行一次写操作（如图书馆预约、设置个人日程）。之后完全退出应用、重新打开，进入「设置 → AI 操作记录」，仍能看到这次操作的时间、工具、风险等级、确认状态与执行结果；点开某一条可看到参数摘要、影响资源、失败原因与验证结论。列表为空时给出明确空态。

**Why this priority**: 审计是"可追溯"的底线。记录只活在一次会话里，用户事后无法证明"AI 到底做了什么"，治理链就形同虚设。

**Independent Test**: 触发任意一次工具调用 → 杀进程重启 → 进入设置页，记录仍在且字段完整；该路径可独立于权限功能验收。

**Acceptance Scenarios**:

1. **Given** 用户已完成一次工具调用, **When** 用户完全退出并重启应用后打开设置页, **Then** 最近一次工具调用的审计记录仍然可见，且工具名、时间、风险、确认状态、执行状态均非空。
2. **Given** 审计列表非空, **When** 用户点击某条记录, **Then** 该条展开并显示参数摘要、结果摘要或错误信息、验证结论；再次点击收起。
3. **Given** 历史上从未发生过工具调用, **When** 用户打开操作记录区, **Then** 显示明确空态文案，不显示空白卡片或错误。
4. **Given** 记录数超过展示上限, **When** 用户打开设置页, **Then** 只展示最近若干条，且顺序为最新在前。

### User Story 2 - 按能力类别关闭 AI 工具 (Priority: P1)

用户不希望 AI 能读写某个子系统（例如校园卡、体育场馆）。在「设置 → AI 权限」中关闭对应能力类别后，AI 不再收到该类工具；即使模型仍然点名调用，也会得到"该能力已在设置中关闭"的可读拒绝，不会发起任何网络请求或本地写入。重新打开开关后能力立即恢复，写操作仍然要求二次确认。

**Why this priority**: "可授权"是本特性的核心价值；没有权限门禁，用户只能被动接受 AI 能触碰的所有能力。

**Independent Test**: 关闭某类能力 → 在 AI 对话中请求该能力 → 观察到工具未被下发/被可读拒绝且无副作用；重新开启后同一请求可正常走确认链。

**Acceptance Scenarios**:

1. **Given** 用户关闭「校园卡」相关能力, **When** 发起一次新的 AI 请求, **Then** 该类工具不出现在提供给模型的工具清单中。
2. **Given** 某能力已关闭, **When** 模型仍然点名调用该类工具, **Then** 系统在预览/确认/执行之前拒绝，返回可读的拒绝结果，且本次调用不产生任何网络写入或本地数据变更。
3. **Given** 某能力已关闭, **When** 用户重新打开该开关, **Then** 下一次 AI 请求立即恢复该工具，无需重启应用。
4. **Given** 某写操作能力处于开启状态, **When** 用户让 AI 执行写操作, **Then** 仍然先展示预览并等待二次确认，确认后才执行。
5. **Given** 用户关闭了任意能力, **When** 用户重启应用后回到 AI 权限页, **Then** 开关状态与关闭前一致。

### User Story 3 - 清空审计记录与脱敏回看 (Priority: P2)

用户想清理本机的 AI 操作痕迹，或确认记录里没有泄露手机号、Cookie、Token 等敏感内容。在操作记录区点击「清空」，经二次确认后记录归零且重启后仍为空；展开任意记录时，敏感字段以打码或占位符呈现，系统日志中也不出现参数原文。

**Why this priority**: 审计本身可能成为隐私泄漏面；没有脱敏与清空能力，审计功能会反过来伤害用户。它不阻塞主流程，故排在 P2。

**Independent Test**: 构造含手机号/Token/长文本的工具参数 → 查看审计记录与设备日志 → 敏感值被打码、日志无原文；清空后重启仍为空。

**Acceptance Scenarios**:

1. **Given** 审计列表有记录, **When** 用户点击清空并在确认框选择"清空", **Then** 列表立即归零，重启应用后仍为空。
2. **Given** 清空确认框已弹出, **When** 用户选择"取消", **Then** 记录保持不变。
3. **Given** 某次工具调用的参数包含手机号、Cookie、Token、学号或超长文本, **When** 用户展开该条审计, **Then** 这些值以打码或占位符呈现，不显示原文。
4. **Given** 任意一次工具调用完成, **When** 查看设备日志, **Then** 日志中不出现工具参数值、结果正文、凭证、Cookie、API Key、手机号、邮箱等敏感明文。

### Edge Cases

- **审计存储为空或解析失败**：读取返回空列表，界面显示空态；不得因损坏的存储阻断 AI 对话或设置页打开。
- **审计写入失败**（存储不可用）：工具执行结果仍正常返回给用户；只记录不含敏感内容的失败日志，不向用户抛出异常。
- **并发/快速连续的工具调用**：多条记录不得互相覆盖或丢失；同一次调用不得产生重复记录。
- **记录数达到上限**：新增记录时淘汰最旧记录，最新记录始终保留。
- **权限关闭发生在一次 AI 请求进行中**：执行阶段必须按最新权限状态判定，已关闭能力不得因"请求开始时还开着"而被执行。
- **全部能力被关闭**：AI 仍可正常对话，只是不带任何工具；不得出现空白崩溃或误导性错误。
- **权限键在工具注册表中不存在**（历史遗留/工具下线）：权限页忽略该键；禁用集合中的孤儿键不得导致过滤异常。
- **关闭权限后请求原本需要确认的写操作**：返回的拒绝信息必须可读，且明确提示"已在设置中关闭"，不能伪装成"未知工具"或"执行失败"。
- **演示模式**：不发起真实请求；权限页开关仍可查看/切换并持久化，行为与正式模式一致。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为每一次已知工具的调用生成一条审计记录（含只读与写操作），写入前完成脱敏，并持久化到本地存储，使记录在进程重启后仍可读取。
- **FR-002**: 审计记录 MUST 至少包含：记录标识、发生时间、工具内部名、工具展示名、风险等级、所属权限键、确认状态、执行状态、参数摘要、结果摘要或错误信息；验证结论存在时 MUST 一并保存。
- **FR-003**: 审计记录 MUST 在写入前脱敏：敏感命名（密码、Token、Cookie、验证码、凭证、手机号、邮箱、学号、账号、卡号、设备标识、IP 等）对应的值 MUST 打码或替换为占位符；超长字符串 MUST 截断；嵌套层级与数组长度 MUST 有上限；循环引用 MUST 安全终止。
- **FR-004**: 审计记录 MUST 设有条数上限（200 条），新记录在前，超出上限时淘汰最旧记录。
- **FR-005**: 设置页 MUST 提供「AI 操作记录」入口（替换现有禁用态），默认展示最近 6 条；每条至少展示工具展示名、时间、风险等级与执行状态。
- **FR-006**: 审计条目 MUST 支持展开/收起：展开后展示权限键、确认状态、影响资源、参数摘要、结果摘要或错误信息、验证结论。
- **FR-007**: 设置页 MUST 提供清空审计的动作，并 MUST 经二次确认；确认后内存列表与持久化记录同时清空，且不影响对话历史。
- **FR-008**: 设置页 MUST 提供「AI 权限」入口，进入独立子页；子页 MUST 按能力类别（每个权限键一行）列出：类别名称、权限键、包含的工具、最高风险等级、是否需要二次确认。
- **FR-009**: AI 权限子页 MUST 为每个类别提供启用/禁用开关，并 MUST 提供"恢复全部权限"动作；页面 MUST 展示已启用类别数与总数。
- **FR-010**: 权限状态 MUST 持久化（独立于审计存储），默认全部启用；切换后 MUST 立即生效，无需重启应用。
- **FR-011**: 权限关闭后，系统 MUST 在构建提供给模型的工具清单时排除该权限下的全部工具。
- **FR-012**: 权限关闭后，若模型仍点名调用该工具，系统 MUST 在预览、确认与执行之前拒绝，返回可读拒绝结果（明确说明该能力已在设置中关闭），并且 MUST NOT 产生任何网络请求或本地写入。
- **FR-013**: 权限关闭导致的拒绝 MUST 写入审计记录，状态为失败，并保留可读的拒绝原因。
- **FR-014**: 权限开启时，现有确认链 MUST 保持不变：需要确认的工具 MUST 先预览、再等待用户确认、确认后才执行、执行后执行验证。
- **FR-015**: 与审计、权限和工具执行相关的日志 MUST NOT 输出参数值、结果正文、凭证、Cookie、API Key、手机号、邮箱等敏感明文；允许输出工具名、轮次、记录条数与非敏感状态。
- **FR-016**: 审计读取失败或数据损坏时 MUST 返回空列表并保持功能可用；审计写入失败 MUST NOT 改变工具执行结果。
- **FR-017**: 新增界面文案 MUST 同时提供中文与英文，不得在服务层硬编码中文文案。
- **FR-018**: 权限与审计界面 MUST 遵循现有设置页的视觉与交互约定（分组标题、开关行、二次确认弹窗、返回导航）。

### Key Entities *(include if feature involves data)*

- **Action Audit Record（操作审计记录）**：一次工具调用的留痕。关键属性：标识、时间、工具名与展示名、风险等级、权限键、确认状态、执行状态、参数摘要、结果摘要、错误信息、验证结论。关系：多条记录构成操作记录列表，按时间倒序。
- **AI Capability Permission（AI 能力权限）**：一个权限键及其下工具集合。关键属性：权限键、展示名称、所含工具、最高风险等级、是否需要二次确认、启用状态。关系：一个权限键对应多个工具；禁用集合由若干权限键组成。
- **Disabled Permission Set（禁用权限集合）**：用户显式关闭的权限键列表，持久化保存，默认空集（全部启用）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 完成一次工具调用后关闭并重启应用，最近一次调用记录 100% 仍可查看（除已超过留存上限被淘汰的记录）。
- **SC-002**: 关闭某类能力后，该类工具在后续请求中 100% 不出现在模型可用工具清单里；直接点名调用时 100% 返回可读拒绝，且副作用为 0。
- **SC-003**: 抽检包含敏感字段的审计记录与设备日志，敏感原文命中数为 0。
- **SC-004**: 从设置页到完成一次权限切换不超过 3 次点击；切换后下一次 AI 请求即生效（无需重启）。
- **SC-005**: 清空操作 100% 需要二次确认；确认后记录数归零，重启后仍为 0；选择取消时记录数不变。
- **SC-006**: 权限全部开启时，需要确认的写操作 100% 仍先展示预览再执行，确认链无回归。
- **SC-007**: 设置页「AI 操作记录」在无记录时给出可读空态，不出现空白或异常。

## Assumptions

- 审计记录保存在与本应用其他偏好一致的本地存储中，只存脱敏后的内容，不做额外加密（已通过脱敏避免敏感原文落盘）。
- 留存上限采用 200 条（与 RN 基线一致），新记录在前，超出淘汰最旧。
- 设置页内嵌展示最近 6 条（与 RN 基线一致），不新增独立审计页；完整历史通过条数上限与滚动查看。
- 权限按单个权限键分组（与 RN 基线一致），当前工具注册表约 27 个权限键；类别展示名按业务域映射。
- 权限默认为全部启用；只持久化"被禁用"的权限键集合，空集合等价于全开。
- 权限切换只影响后续工具清单构建与后续调用，不追溯修改历史对话内容。
- 审计记录不提供单条删除与导出，仅支持整体清空。
- 不改变现有工具的风险等级、确认要求与执行逻辑，也不新增工具。
- 现有的内存审计接口在改造后仍保持可读取性，避免影响尚未接入的调用方。
- 新增文案通过现有国际化机制注册中英文，满足 FR-017。

## Open Questions

- 审计记录是否需要纳入设置页「清除本地数据」的一并清理范围？（本轮默认不纳入，保持"只在操作记录区清空"的单一入口。）
- 审计列表后续是否需要按风险/结果筛选与分页？（本轮不做，仅最近 6 条 + 展开。）
