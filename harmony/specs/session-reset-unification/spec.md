# Feature Specification: 会话复位统一（子系统"已确保"标志与瞬态缓存）

**Created**: 2026-10-16
**Status**: Draft
**Input**: User description: "随后进行会话健壮性统一"——将体育/图书馆座位/研读间/邮件/校园网等服务的"已确保"标志统一纳入会话复位入口（经澄清：纳入**全部有瞬态态的服务**；spec 产物新建 `session-reset-unification` 目录）。

## Overview

当前"退出登录 / 登录成功 / 2FA 成功"的统一会话复位入口（`SessionManager`）**仅复位 `CampusDataService`** 的瞬态标志；体育、图书馆座位（含访问令牌与时段缓存）、研读间（cab 账号号）、邮件（Coremail 会话）、校园卡（账号缓存）等服务的瞬态态**未被复位**。进程内"退出 → 再登录"后，这些陈旧态可能被复用，导致首次拉取失败、串账号或需二次操作。

本特性将这些服务的瞬态会话态**统一纳入单一复位入口**：各服务暴露一致的复位方法，由 `SessionManager` 在既有 3 个触发点统一扇出（仅针对已实例化服务，不强制创建）。不改动 Cookie、凭证与认证服务的 csrf 语义。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 进程内重登后各子服务首次访问可用 (Priority: P1)

用户在应用内"退出登录 → 再登录"（或 2FA 通过）后，首次访问体育、图书馆座位、研读间、邮件、校园卡等服务时，不应复用上一会话的"已确保"标志或缓存：应重新建立各自会话并正常返回数据，无需用户手动重试或额外操作。

**Why this priority**: 这是用户可感知的核心缺陷——陈旧标志导致"重登后首次拉取失败且不自愈"。

**Independent Test**: 在真实登录态下依次访问上述服务（使其建立会话）→ 退出 → 重新登录 → 再次访问，观察是否无需额外操作即可成功。

**Acceptance Scenarios**:

1. **Given** 用户已登录并访问过体育/图书馆座位/研读间/邮件/校园卡（各自会话已建立、缓存已写入），**When** 退出登录后再重新登录，**Then** 首次访问各服务均能重新建立会话并返回数据（不因陈旧"已确保"标志而跳过重建）
2. **Given** 图书馆座位服务已缓存访问令牌与时段，**When** 重登后首次预约/查询，**Then** 使用新会话（不复用旧令牌/旧时段）
3. **Given** 研读间服务已缓存 cab 账号号，**When** 重登后首次访问，**Then** 重新校验并缓存新会话的账号号

---

### User Story 2 - 复位入口统一且可扩展 (Priority: P2)

复位行为由**单一入口**统一扇出；各服务以一致的复位方法暴露瞬态态清理，便于后续新增服务低成本纳入。

**Why this priority**: 避免"新增服务忘记接入复位"再次产生同类缺陷（工程可持续性）。

**Independent Test**: 检查复位入口是否统一调用各服务的复位方法，且新增一个服务仅需实现同签名方法并在入口登记。

**Acceptance Scenarios**:

1. **Given** 复位入口，**When** 触发复位，**Then** 逐一调用各（已实例化的）服务的复位方法
2. **Given** 某服务尚未被实例化，**When** 触发复位，**Then** 不因复位而创建该服务实例

---

### User Story 3 - 复位无副作用 (Priority: P2)

统一复位不得引入副作用：不清 Cookie、不改动凭证、不复位认证服务的 csrf（保持学习会话语义），异常不得中断登录/退出流程。

**Why this priority**: 复位是登录/退出的关键路径，任何副作用都会放大为登录异常或学习页回归。

**Independent Test**: 触发复位后，确认 Cookie 与凭证不变、学习页无 `no_csrf` 回归、登录/退出流程不中断。

**Acceptance Scenarios**:

1. **Given** 已登录且 Cookie/凭证就绪，**When** 触发统一复位，**Then** Cookie 与凭证保持不变
2. **Given** 登录成功流程，**When** 复位执行，**Then** 认证服务 csrf 不被清空（学习页首次加载不出现 `no_csrf`）
3. **Given** 某服务复位方法异常，**When** 触发统一复位，**Then** 其余服务的复位与登录/退出流程继续完成（不中断）

---

### Edge Cases

- 目标服务尚未被实例化：复位应跳过（惰性），不得为复位而创建实例
- 某服务复位方法抛错：应被隔离，不影响其它服务与登录/退出主流程
- 复位重复触发（幂等）：多次复位结果一致，无累积副作用
- 认证服务的 transient（csrf/凭证）保持既有处理：不在本特性范围

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 退出登录、登录成功、2FA 成功时，必须统一复位各校园子服务的瞬态会话态（"已确保"标志与瞬态缓存）
- **FR-002**: 复位范围至少覆盖：`CampusDataService`（既有）、`SportsService`、`LibrarySeatService`（含访问令牌与时段缓存）、`LibraryRoomService`（含 cab 账号号）、`MailService`（邮件会话）、`CampusCardService`（账号缓存）
- **FR-003**: 复位必须对"未实例化"的服务安全：不得为复位而强制创建服务实例
- **FR-004**: 复位 MUST NOT 清除 Cookie、MUST NOT 改动持久化凭证（信任策略由调用方处理）
- **FR-005**: 复位 MUST NOT 复位认证服务的 csrf（保持既有学习会话语义，避免 `no_csrf` 回归）
- **FR-006**: 复位必须幂等且容错：单个服务复位异常不得中断其余复位与登录/退出流程
- **FR-007**: 各服务 MUST 暴露一致签名的复位方法，便于后续服务低成本接入统一入口
- **FR-008**: `CampusNetworkService` 无瞬态会话态，本特性不要求改动（如为形态统一而预留，须为无操作且不影响既有行为）

### Key Entities *(include if feature involves data)*

- **瞬态会话态**：进程内、随会话建立的"已确保"标志与缓存（不属于 Cookie/凭证），如：体育子系统会话标志、图书馆座位子系统会话标志 + 访问令牌/时段缓存、研读间 cab 账号号、邮件会话、校园卡账号缓存
- **统一复位入口**：在登录成功 / 2FA 成功 / 退出登录三处调用的单一扇出点
- **复位方法**：各服务暴露的一致签名方法（无参、同步、幂等、不抛）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 进程内"访问各子服务 → 退出 → 重登 → 再访问"，各服务首次访问成功率 = 100%（修复前存在因陈旧标志导致的失败）
- **SC-002**: 复位对未实例化服务**不产生实例化**（实例计数增量 = 0）
- **SC-003**: 复位前后 Cookie 与持久化凭证**保持不变**（0 处改动）
- **SC-004**: 学习页回归失败数 = 0（无 `no_csrf`）
- **SC-005**: 复位异常不影响登录/退出流程（流程中断率 = 0）

## Assumptions

- 复位触发点沿用既有 3 处（登录成功、2FA 成功、退出登录），不新增触发点
- 各服务的瞬态态均为**进程内内存态**，无跨进程/跨启动持久化
- `TsinghuaAuthService` 的 csrf 与凭证处理保持既有语义（已有注释说明：登录成功后复位会清空新 csrf → 学习页 `no_csrf`）
- `CampusNetworkService` 无瞬态会话态
- 复位方法为同步、无参、幂等、不抛（异常在入口处隔离）

## Open Questions

- 是否统一为 `CampusNetworkService` 预留无操作复位以保持形态一致（默认否）
