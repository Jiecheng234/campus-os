# Feature Specification: 清华邮件接入（Coremail 读写）

**Created**: 2026-10-11
**Status**: Draft
**Input**: User description: "先接入清华邮箱子页面数据"（经澄清：**含写操作（含发送）**；全部 5 个系统文件夹；需要搜索；附件仅展示信息）

## Overview

在"校园 → 校园邮件"接入清华大学 Coremail 邮箱的真实数据：浏览**系统文件夹**（收件箱 / 草稿箱 / 已发送 / 已删除 / 垃圾邮件）与**邮件列表**（分页、未读与附件标记）、**阅读邮件详情**（收发抄送、时间、正文、附件元信息）、**关键词搜索**；并支持写操作：**标记已读、删除、移动、发送新邮件**。会话经信息门户漫游建立 Coremail 会话并在失效时自动重建。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 浏览文件夹与邮件列表 (Priority: P1)

用户进入"校园邮件"，看到文件夹与当前文件夹的邮件列表（发件人、主题、摘要、时间、未读标记、附件标记）与未读计数；切换文件夹刷新列表，可加载更多。

**Why this priority**: 列表是全部后续能力（详情/搜索/写操作）的入口，单此一项即可交付价值。

**Independent Test**: 进入页面即见收件箱列表与未读计数；切换文件夹后列表随之刷新。

**Acceptance Scenarios**:

1. **Given** 已登录且会话有效，**When** 进入校园邮件页，**Then** 默认展示收件箱邮件列表（含发件人/主题/摘要/时间/未读与附件标记）与未读计数
2. **Given** 已展示列表，**When** 切换到另一文件夹（草稿箱/已发送/已删除/垃圾邮件），**Then** 列表按该文件夹刷新
3. **Given** 列表超过一页，**When** 加载更多，**Then** 追加下一页且不重复
4. **Given** 邮箱会话失效，**When** 进入或刷新，**Then** 自动重建会话后重试；仍失败展示可读错误与"重试"

---

### User Story 2 - 阅读邮件详情 (Priority: P2)

用户点击某封邮件，进入详情：发件人、收件人、抄送、主题、时间、正文，以及附件名称与大小。

**Why this priority**: 阅读是邮箱的核心用途；依赖列表已有数据。

**Independent Test**: 点击任一邮件即可看到详情字段与正文；有附件时看到附件元信息。

**Acceptance Scenarios**:

1. **Given** 已展示列表，**When** 点击某封邮件，**Then** 展示发件人/收件人/抄送/主题/时间/正文
2. **Given** 该邮件含附件，**When** 详情加载完成，**Then** 展示附件名称与大小（不下载）
3. **Given** 正文为富文本，**When** 渲染，**Then** 内容可读且不出现乱码或脚本内容

---

### User Story 3 - 搜索邮件 (Priority: P3)

用户输入关键词搜索邮件，看到结果列表，可点开任意结果查看详情。

**Why this priority**: 邮件量较大时检索是高频诉求；可与列表复用同一套展示。

**Independent Test**: 输入关键词后看到结果列表，点击结果能打开详情。

**Acceptance Scenarios**:

1. **Given** 已进入邮箱页，**When** 输入关键词并搜索，**Then** 展示匹配邮件列表
2. **Given** 搜索结果，**When** 点击某项，**Then** 打开详情
3. **Given** 无匹配结果，**When** 搜索完成，**Then** 展示空态提示

---

### User Story 4 - 标记已读 (Priority: P4)

用户打开邮件后，该邮件被标记为已读；列表中的未读标记与未读计数随之更新。

**Why this priority**: 已读状态是邮箱的基本语义，且为避免"看过仍是未读"的困扰。

**Independent Test**: 打开一封未读邮件后，返回列表可见该项变为已读、未读计数减一。

**Acceptance Scenarios**:

1. **Given** 列表中有未读邮件，**When** 打开其详情，**Then** 该邮件被标记为已读
2. **Given** 标记成功，**When** 返回列表，**Then** 未读标记消失、未读计数相应减少
3. **Given** 标记失败，**When** 发生异常，**Then** 不阻塞阅读，给出可读提示（不打断）

---

### User Story 5 - 删除与移动邮件 (Priority: P5)

用户删除某封邮件，或将邮件移动到另一文件夹；两者均需二次确认，失败需展示可读原因。

**Why this priority**: 邮箱管理的基本操作；需谨慎确认以避免误删。

**Independent Test**: 删除后该邮件从当前列表消失；移动后目标文件夹可见该邮件。

**Acceptance Scenarios**:

1. **Given** 列表或详情中的邮件，**When** 触发删除，**Then** 弹出二次确认；取消无变化
2. **Given** 确认删除，**When** 服务端成功，**Then** 提示成功并刷新列表
3. **Given** 触发移动，**When** 选择目标文件夹，**Then** 确认后执行移动；成功提示并刷新
4. **Given** 删除/移动失败，**When** 服务端返回失败，**Then** 展示可读原因

---

### User Story 6 - 撰写并发送邮件 (Priority: P6)

用户撰写邮件（收件人、抄送、主题、正文）并发送；发送前需二次确认；成功或失败均给出明确反馈。

**Why this priority**: 覆盖"回复/告知"类需求；属不可逆的写操作，风险最高，置于最后交付。

**Independent Test**: 填写最小必填项后发送，得到成功反馈；缺必填项时给出校验提示。

**Acceptance Scenarios**:

1. **Given** 撰写页，**When** 未填写收件人或主题，**Then** 发送按钮给出校验提示（不发出）
2. **Given** 已填写必填项，**When** 点击发送，**Then** 弹出二次确认；确认后发送
3. **Given** 发送成功，**When** 返回列表，**Then** 提示已发送（已发送文件夹可见，若刷新）
4. **Given** 发送失败，**When** 服务端返回失败，**Then** 展示可读原因且不丢失已填写内容

---

### Edge Cases

- 邮箱会话失效 / 返回未登录标记时：应自动重建会话（清空缓存后重试一次）后重试；仍失败给可读错误与重试入口
- 接口返回非 JSON、或返回"已返回邮件但无法解析结构"时：应转为可读错误（提示适配问题），禁止崩溃或暴露原始报文
- 列表接口需在"线程/扁平/兼容"多种形态间回退；全部失败时展示空态 + 可重试
- 空文件夹、无搜索结果：展示空态
- 富文本正文：不得执行脚本；不得出现编码乱码
- 演示模式（未登录或演示开关开启）：使用内置示例数据，不发起任何网络请求
- 写操作在演示模式下不发起请求（给出提示）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: "校园邮件"入口必须接入真实数据；未登录/演示模式使用内置示例且零网络请求
- **FR-002**: 必须展示系统文件夹（收件箱/草稿箱/已发送/已删除/垃圾邮件），默认选中收件箱
- **FR-003**: 必须展示当前文件夹的邮件列表（发件人、主题、摘要、时间、未读标记、附件标记）与未读计数
- **FR-004**: 必须支持分页加载更多（追加去重）与手动刷新
- **FR-005**: 必须支持点击邮件进入详情：发件人、收件人、抄送、主题、时间、正文
- **FR-006**: 详情必须展示附件元信息（名称、大小）；**不下载**附件
- **FR-007**: 必须支持关键词搜索并展示结果列表，结果可打开详情；无结果展示空态
- **FR-008**: 打开未读邮件时必须标记为已读，并反映到列表标记与未读计数；标记失败不阻塞阅读
- **FR-009**: 必须支持删除邮件，操作前二次确认；成功提示并刷新，失败展示可读原因
- **FR-010**: 必须支持将邮件移动到其他文件夹（选择目标），操作前二次确认；成功提示并刷新
- **FR-011**: 必须支持撰写并发送邮件（收件人、抄送、主题、正文）；发送前二次确认；必填校验；成功/失败均有明确反馈，失败不丢失草稿内容
- **FR-012**: 邮箱会话失效时必须自动重建并重试（最多一次强制重建）；仍失败展示可读错误与"重试"
- **FR-013**: 接口异常（非 JSON / 结构无法解析 / 业务错误码）必须转为可读中文错误，禁止崩溃或暴露原始报文
- **FR-014**: 富文本正文渲染不得执行脚本；中文不得乱码
- **FR-015**: 卡片与列表布局必须遵循项目约定（全宽卡片配 `constraintSize` 防右缘溢出）

### Key Entities *(include if feature involves data)*

- **文件夹**：标识、名称、系统类型（收件箱/草稿箱/已发送/已删除/垃圾邮件）
- **联系人**：显示名、地址
- **邮件摘要**：标识、所属文件夹、发件人、收件人、主题、日期、未读、星标、含附件、摘要文本
- **邮件详情**：摘要 + 抄送、正文（纯文本/富文本）、附件列表
- **附件**：标识、名称、大小（仅元信息）
- **草稿**：收件人、抄送、密送、主题、正文（用于发送）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 已登录用户进入校园邮件页，在网络正常时 3 秒内看到收件箱列表与未读计数
- **SC-002**: 打开邮件详情在 3 秒内呈现正文与附件元信息
- **SC-003**: 关键词搜索在 5 秒内呈现结果（或空态）
- **SC-004**: 写操作（标记已读/删除/移动/发送）反馈时间 ≤ 5 秒；成功后列表在 3 秒内反映变化
- **SC-005**: 会话失效场景下，用户无需手动重新登录即可在自动重建后看到数据（成功率 ≥ 90%）
- **SC-006**: 演示模式下页面 100% 离线可用（零网络请求）
- **SC-007**: 接口异常或会话不可恢复时，100% 展示可读中文错误（无崩溃、无原始报文）
- **SC-008**: 正文渲染 0 脚本执行、0 乱码

## Assumptions

- 采用 Coremail 网页版 JSON 接口（`sid` 会话）；会话经**信息门户漫游**建立并缓存（约 20 分钟），失效时清缓存并强制重建一次
- 列表接口需在多种形态（线程/扁平/兼容接口）间回退；解析需容错，无法解析时给可读错误
- 富文本正文以**受控 Web 渲染**（禁脚本）呈现；纯文本可作降级展示
- **附件仅展示元信息**，不支持下载或在线预览
- **草稿保存不在本轮**（草稿箱仅作只读展示）；发送为不可逆操作，需二次确认
- 写操作成功以服务端返回为准；失败展示服务端消息
- 入口沿用现有"校园邮件"页（`pages/campus/MailPage.ets`），采用**页内多级**（列表 → 详情 → 撰写），不新增校园页分发项
- 沿用现有页面约定：真实/演示双模式、错误可重试、中文 UI 文案、右上角刷新

## Open Questions

- 删除语义：是"移入已删除"还是"永久删除"（以服务端接口语义为准，UI 文案随之而定）
- 发送是否需要"回复/转发"入口（当前仅"撰写新邮件"）
- 列表每页条数（参考为 30）与"加载更多"触发方式（滚动到底 vs 按钮）
