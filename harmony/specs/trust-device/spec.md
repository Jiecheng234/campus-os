# Feature Specification: 信任此设备与会话门控（含退出登录回登录页）

**Created**: 2026-10-13
**Status**: Draft
**Input**: User description: "进行 4、5 两项"——`4. 信任此设备应当在登录时加入选择；未选择信任或在设置页取消后，本次登录结束（应用退出）时清除凭证，但不影响使用过程中的会话复用；并核对原应用是否处理服务端信任浏览器数量浪费问题（上限 15、可能过期，需在需要再次 2FA 时及时进入 2FA 界面）`；`5. 退出登录后整应用回登录页`

**参考核对结论（用户要求）**：参考 RN 项目**仅持久化 `trustDevice`、在登录/凭证/2FA 链路上从未消费**，即**上游未实现**"不信任清凭证""信任额度节约""2FA 复现进界面"等能力 → 本特性为新增设计，无参考可对齐。

## Overview

引入**信任此设备**策略与会话门控：登录页提供信任选择（默认值＝用户上次选择）；**信任 → 持久化凭证**（支持自动登录），**不信任 → 仅内存会话**（应用退出即失效）；设置页取消信任 → 标记并在**应用退出时清除**已存凭证（被强杀则由启动兜底清除）；自动登录遇到服务端要求 2FA（信任数超限/过期等）→ **直接进入 2FA 界面**；退出登录 → **整应用回到登录页**。运行期会话复用（漫游/请求/会话恢复）不受信任策略影响。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 登录时选择是否信任此设备 (Priority: P1)

登录页提供"信任此设备"选项，默认值等于用户上次的选择（无历史则默认不勾选）；勾选则凭证被持久化（下次可自动登录），不勾选则凭证仅存在于本次运行内。

**Why this priority**: 这是信任策略的入口，直接决定凭证是否落盘与自动登录是否可用。

**Independent Test**: 勾选登录 → 冷启动自动登录成功；不勾选登录 → 冷启动停在登录页（不自动登录）。

**Acceptance Scenarios**:

1. **Given** 登录页首次使用（无历史选择），**When** 打开登录页，**Then** "信任此设备"**默认不勾选**
2. **Given** 上次登录勾选过信任，**When** 再次打开登录页，**Then** 该选项**默认勾选**
3. **Given** 勾选信任并登录成功，**When** 冷启动应用，**Then** **自动登录成功**
4. **Given** 未勾选信任并登录成功，**When** 应用退出后再次启动，**Then** **不自动登录**（凭证未被持久化）

---

### User Story 2 - 取消信任与退出清理 (Priority: P2)

用户在设置页取消"信任此设备"后：本次运行内会话继续可用；**应用退出时清除**已持久化的凭证；若应用被强制结束，则**下次启动兜底清除**；重新开启信任后，后续登录恢复持久化。

**Why this priority**: 决定"取消信任"是否真正生效（含异常退出场景），关系到账号安全与信任额度。

**Independent Test**: 信任登录后在设置页取消信任 → 正常退出应用 → 再次启动不自动登录且凭证已清除；强杀场景下启动亦完成清除。

**Acceptance Scenarios**:

1. **Given** 已信任登录，**When** 在设置页取消信任，**Then** 状态标记为未信任，**且本次运行内会话继续可用**
2. **Given** 已取消信任，**When** 正常退出应用后再启动，**Then** 凭证**已被清除**且**不自动登录**
3. **Given** 已取消信任后被**强制结束**，**When** 下次启动，**Then** 启动兜底**清除残留凭证**
4. **Given** 已取消信任，**When** 在设置页重新开启信任并重新登录，**Then** 凭证恢复持久化（不再被兜底清除）

---

### User Story 3 - 自动登录需 2FA 时进入 2FA 界面 (Priority: P3)

自动登录时代服务端要求二次认证（如信任浏览器数量超限、信任过期、服务端手动清除）时，应用**直接进入 2FA 界面**并保留待验证状态，且给出可读提示，而不是静默停在登录页。

**Why this priority**: 避免"自动登录静默失败"造成的困惑；及时进入 2FA 是保持可用性的关键路径。

**Independent Test**: 构造需 2FA 的自动登录场景 → 应用进入 2FA 界面并给出"需要二次认证"提示，验证后可继续使用。

**Acceptance Scenarios**:

1. **Given** 存在持久化凭证，**When** 自动登录返回"需要 2FA"，**Then** 应用**进入 2FA 界面**（含可读提示）
2. **Given** 已进入 2FA 界面，**When** 用户完成验证，**Then** 登录成功并可正常使用
3. **Given** 自动登录因其它原因失败（网络/凭证无效），**When** 发生，**Then** 给出可读提示并回到登录页（不进入 2FA 界面）

---

### User Story 4 - 退出登录后整应用回登录页 (Priority: P4)

用户退出登录后，**整个应用**（含底部导航与各页）回到登录页；冷启动亦为登录页。

**Why this priority**: 修复"退出后仍可访问各 Tab"的越权观感（此前因约束未做门控联动）。

**Independent Test**: 退出登录后界面切换为登录页且无法访问底部 Tab；冷启动为登录页。

**Acceptance Scenarios**:

1. **Given** 已登录，**When** 在设置页退出登录，**Then** 界面**整应用切换为登录页**（底部导航不可见/不可用）
2. **Given** 已退出登录，**When** 冷启动应用，**Then** 停留在登录页
3. **Given** 会话在运行中失效（如被服务端清除），**When** 被检出，**Then** 亦按未登录态处理（整应用回登录页）

---

### User Story 5 - 运行期会话复用不受影响 (Priority: P5)

未信任或已取消信任的状态下，本次运行内的会话复用（后续请求、子系统漫游、会话恢复）行为与信任时一致。

**Why this priority**: 用户明确要求"不影响使用过程中的会话复用"。

**Independent Test**: 不信任登录后，在本次运行内正常使用各功能（课表/成绩/校园等），无额外重登或中断。

**Acceptance Scenarios**:

1. **Given** 未信任登录成功，**When** 本次运行内使用需要会话的功能，**Then** 正常可用（不触发额外登录/清会话）
2. **Given** 已取消信任，**When** 本次运行内继续使用，**Then** 正常可用（不中断）

---

### Edge Cases

- 未信任登录后应用被**强杀**：不得留下可自动登录的残留（启动兜底清除）
- 取消信任后**未退出**即重新登录并再次勾选信任：以最近一次选择为准（恢复持久化）
- 2FA 过程中退出应用：不产生半登录状态；下次启动按凭证策略处理
- 凭证已过期/被服务端清除：自动登录失败 → 按其类型分别进入 2FA 界面或登录页
- 演示模式：不涉及信任策略（不写凭证、零网络请求）；退出登录回登录页语义同样成立
- 冷启动自检（既有 `Phase4SelfTest`）**不得**写入/清除凭证而破坏信任策略

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 登录页必须提供"信任此设备"选择项
- **FR-002**: 该选择的**默认值必须等于用户上次的选择**（无历史记录时默认**不勾选**）
- **FR-003**: 选择信任时，登录成功后**必须持久化凭证**（既有安全存储，不落明文偏好）
- **FR-004**: 选择不信任时，**禁止持久化凭证**（本次运行仅内存会话；退出后无法自动登录）
- **FR-005**: 必须持久化"未信任"状态标记，并在**应用启动时兜底清除**可能残留的已持久化凭证
- **FR-006**: 设置页取消信任时必须标记状态；已持久化凭证在**应用退出时清除**（异常退出由 FR-005 兜底）
- **FR-007**: 设置页重新开启信任后，后续登录恢复持久化（并解除待清除状态）
- **FR-008**: 信任策略**不得影响运行期会话复用**（不清会话、不打断请求/漫游/会话恢复）
- **FR-009**: 自动登录遇到服务端要求 2FA 时，必须**直接进入 2FA 界面**并保留待验证状态
- **FR-010**: 上述情形必须给出可读提示（如"需要二次认证"）；其它失败类型给出对应可读提示并回登录页
- **FR-011**: 退出登录后必须**整应用回到登录页**（含底部导航/内容区），冷启动亦为登录页
- **FR-012**（**2026-10-13 修订**）：退出登录必须**仅清除会话**；**凭证按信任策略处理**——**信任开启时保留凭证**（以支持下次"一键登录"与自动登录）；**未信任时不得留下凭证残留**
- **FR-017**（新增）：信任开启且存在已保存凭证时，登录页必须**回填已保存的学号与密码**，用户**仅需点击登录**
- **FR-018**（新增）：在"存在已保存凭证 + 信任开启"的情况下，点击登录且**服务端未要求 2FA** 时，必须**直接进入主页**（不得停留在 2FA 视图或要求再次输入密码）
- **FR-013**: 启动自检等既有自动化逻辑**不得**写入或清除凭证而破坏信任策略
- **FR-014**: 演示模式与未登录路径既有约束不变（零请求等）
- **FR-015**: 新增/改动文案必须走 i18n（`login.*` / `settings.*` 扩展，zh/en 成对）
- **FR-016**: 日志与错误信息**不得**输出密码或凭证明文

### Key Entities *(include if feature involves data)*

- **信任偏好**：是否信任此设备（持久化"上次选择"用于登录页默认值）
- **未信任标记**：指示启动时需兜底清除残留凭证
- **凭证**：学号/密码/指纹（既有安全存储；仅信任时持久化）
- **登录态**：已登录/未登录/待 2FA（驱动整应用门控）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 信任登录 → **冷启动自动登录成功**；不信任登录 → 冷启动**停在登录页**（两种情况 100% 稳定复现）
- **SC-002**: 取消信任 → **正常退出后再启动**：凭证已清除且不自动登录（100%）
- **SC-003**: 取消信任 → **被强杀后再启动**：启动兜底完成凭证清除（100%）
- **SC-004**: 自动登录需 2FA 时 **100% 进入 2FA 界面**并给出可读提示
- **SC-005**: 退出登录后 **100% 整应用回登录页**；冷启动亦为登录页
- **SC-006**: 未信任/取消信任状态下，运行期会话复用**回归通过**（课表/成绩/校园等可用，无额外重登）
- **SC-007**: 偏好设置中**无凭证明文**；日志**无**密码/凭证明文
- **SC-008**: 演示模式仍**零网络请求**

## Assumptions

- "应用退出时清除"通过**正常退出钩子**实现；**强杀/异常退出由启动兜底**覆盖（ArkTS 无法可靠捕获进程被杀，故必须双保险）
- **不信任＝不持久化凭证**（仅内存），语义上等价于"退出即清除"，且天然覆盖强杀场景
- "上次选择"的记忆存于偏好设置（非敏感布尔/标记）
- 2FA 界面**复用既有 2FA 流程与 UI**，不新造页面；仅新增"自动登录 → 2FA"的进入路径与提示
- **本特性解除**此前"不改导航装配"的约束：允许改动 `Index`/入口装配以实现登录态门控
- 退出登录仍清除凭证（与既有约定一致）；信任策略只影响非退出场景下的凭证持久化
- 服务端信任浏览器数量上限/有效期**不由客户端管理**（无 API），客户端只做"节约额度 + 需要时及时 2FA"两件事

## Open Questions

- 不信任时是否仍需"记住学号"（仅学号、不含密码，便于下次输入）——当前假设**不记住任何凭证**
- 取消信任时是否需要在 UI 明示"退出后需重新登录并可能触发 2FA"
- 是否需要在设置页展示"信任额度"相关信息（服务端疑似不提供）
