# Feature Specification: 凭证安全存储（系统关键资产存储 + 自动迁移）

**Created**: 2026-10-11
**Status**: Draft
**Input**: User description: "同时推进密码明文存储修复与对接新版场馆系统"（经澄清：新版场馆系统**暂缓**；本轮仅做凭证安全存储修复；方案＝系统关键资产存储；存量＝自动迁移）

## Overview

当前登录凭证（学号、密码、指纹）以"偏好设置 + URL 编码"方式落盘，等价于**明文存储**。本特性将其迁移到**系统关键资产存储**（Asset Store Kit，简称 ASSET）：加解密与访问控制均在安全环境执行，业务只持有别名与属性。首次读取时**自动迁移**已有明文凭证到新存储并清除旧明文，保证用户无需重新登录；对上层调用方保持既有接口与语义不变，从而不影响自动登录、会话恢复与校园网验证码登录等既有链路。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 新登录凭证以安全存储保存 (Priority: P1)

用户登录成功后，凭证（学号/密码/指纹）被写入系统关键资产存储，偏好设置中不再出现包含密码的明文记录。

**Why this priority**: 这是修复的核心——消除明文落盘；单此一项即完成安全目标。

**Independent Test**: 登录后检查偏好设置中不存在含密码的明文值；重启应用可自动登录成功。

**Acceptance Scenarios**:

1. **Given** 用户完成登录，**When** 凭证被持久化，**Then** 凭证存于系统关键资产存储，偏好设置中无含密码的明文记录
2. **Given** 已保存凭证，**When** 冷启动触发自动登录，**Then** 能读到凭证并成功重建会话（行为与既有版本一致）
3. **Given** 同一用户再次登录（覆盖保存），**When** 保存执行，**Then** 不出现重复/残留的多份凭证

---

### User Story 2 - 自动迁移既有明文凭证 (Priority: P2)

升级前已保存明文凭证的用户，首次读取凭证时系统自动迁入新存储并清除旧明文，用户无需重新登录。

**Why this priority**: 决定升级体验；不做迁移会强制全部用户重新登录。

**Independent Test**: 在存在旧明文的设备上启动并触发一次读取，旧明文被写入新存储后清除，自动登录成功。

**Acceptance Scenarios**:

1. **Given** 设备上存在旧明文凭证且新存储暂无数据，**When** 首次读取凭证，**Then** 旧值被写入新存储、旧明文被清除，并返回该凭证
2. **Given** 迁移已完成，**When** 再次读取，**Then** 直接命中新存储，不再触及旧明文（幂等）
3. **Given** 迁移过程中新存储写入失败，**When** 发生异常，**Then** 不得清除旧明文（不丢数据）且给出可读日志

---

### User Story 3 - 读取与清除语义保持不变 (Priority: P3)

上层调用方无需改动：无凭证时读取返回空值；注销时凭证被清除（新旧存储均无残留）。

**Why this priority**: 保证既有链路零回归；属于接口兼容性约束。

**Independent Test**: 无凭证时读取得到空值；执行注销后读取得到空值且旧明文不存在。

**Acceptance Scenarios**:

1. **Given** 从未登录（无任何凭证），**When** 读取凭证，**Then** 返回空值（不抛异常）
2. **Given** 已登录，**When** 执行注销，**Then** 凭证被清除（新存储与旧明文字段均为空），后续读取返回空值

---

### Edge Cases

- 新存储不可用（设备/系统限制）时：读取返回空值并记录可读日志；**禁止**回退为明文写入
- 关键资产被用户/系统清除或应用证书变化导致无法访问时：按"无凭证"处理（走重新登录），不崩溃
- 迁移后旧明文字段清除失败（如存储异常）：不影响本次读取结果，但需记录日志并在下次读取时重试清除
- 日志与错误信息中**不得出现密码明文**
- 指纹值必须原样保留与复用（避免设备信任数超限）
- 偏好设置中的其它数据（设置项等）不受本特性影响

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 必须使用系统关键资产存储保存学号、密码、指纹三项；**禁止**再将含密码的内容写入偏好设置
- **FR-002**: 保存必须幂等——重复保存（同别名）应更新而非产生多份残留
- **FR-003**: 读取时若新存储无数据而旧明文字段存在，必须**自动迁移**（写入新存储 → 清除旧明文 → 返回凭证）
- **FR-004**: 迁移失败时**不得清除旧明文**（保证不丢数据），并记录可读日志
- **FR-005**: 读取接口对上层保持既有语义：无数据/异常 → 返回空值，不抛异常到调用方
- **FR-006**: 清除操作必须同时清除新存储与本模块写入的旧明文字段
- **FR-007**: 指纹值必须原样保存与读取（不得变更其内容）
- **FR-008**: 新存储不可用或操作失败时不得崩溃，且**不得降级为明文写入**
- **FR-009**: 所有日志/错误信息中不得输出密码明文（允许输出掩码或长度）
- **FR-010**: 迁移必须幂等（重复启动/重复读取不重复迁移、不产生冗余）

### Key Entities *(include if feature involves data)*

- **凭证记录**：学号、密码、指纹（三项，整体作为一条关键资产或拆分存储，实现可自定）
- **关键资产别名与属性**：用于标识该凭证记录的别名，以及访问控制相关属性（如可访问条件）
- **旧明文记录**：迁移前存于偏好设置的字符串（仅用于迁移与清除，迁移后不应再出现）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 登录并保存凭证后，偏好设置中**不存在**包含密码的明文记录（可检查项）
- **SC-002**: 升级前已有明文凭证的用户，升级后**首次启动自动登录成功**（无需重新登录）
- **SC-003**: 注销后新旧存储均**无**凭证残留（读取返回空值）
- **SC-004**: 迁移或读取失败时，100% 记录可读日志且**不崩溃**、**不丢数据**
- **SC-005**: 既有链路回归通过：自动登录、会话恢复、校园网验证码登录均与修复前一致

## Assumptions

- 采用系统关键资产存储的"无需用户额外认证"能力，访问条件为"设备开机后可用"（设备重启需重新登录——与既有语义一致：会话 Cookie 不持久化、冷启动重新登录）
- 目标数据仅为凭证三项；设置项、演示开关等其它偏好不在范围内
- 上层接口保持不变（保存/读取/清除 的签名与语义不变），调用方（认证服务、会话管理、校园网服务）无需改动逻辑
- 迁移为**惰性**触发（在读取路径），不引入启动时的一次性迁移任务
- 应用中另有一处"HUKS 桥接桩模块"（未接入当前凭证链路）不在本特性范围内，保持现状并在开发文档中注明
- 应用卸载会清除关键资产，无需额外清理逻辑

## Open Questions

- 凭证三项是"单条关键资产合并存储"还是"拆分多条"（影响别名设计与迁移粒度）
- 是否需要为关键资产设置"需用户认证"属性（当前假设不需要，以保持自动登录）
- 是否需要在设置页新增"清除凭证"入口（当前无，倾向保持现状）
