# Feature Specification: 宿舍洗衣机信息（只读）

**Created**: 2026-10-16
**Status**: Draft
**Input**: User description: "接入宿舍洗衣机信息"（经澄清：入口为"宿舍"页内子层；机台范围 = 全部类型 + 位置/ETA；spec 产物新建 `campus-laundry` 目录）。

## Overview

在既有"校园 → 宿舍"页内新增"洗衣机"子层（与电费并列/切换），展示宿舍洗衣机**只读**实时信息：按平台分组的楼宇列表（洁力：紫荆/南区/双清/其他；海乐生活）→ 楼层 → 机台（洗衣机/洗鞋机/烘干机）状态（空闲/使用中/异常），洁力机台附剩余时间（ETA）与更新时间及位置。数据来源为第三方洗衣平台公开接口（无需登录态）；演示模式下使用内置示例、零网络请求。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看洗衣机楼宇分组 (Priority: P1)

用户进入"宿舍 → 洗衣机"，看到按平台/区域分组的楼宇列表（如"紫荆公寓""南区宿舍""双清公寓""其他位置""海乐生活"，仅展示有数据的组）。

**Why this priority**: 楼宇分组是最高频诉求（先定位宿舍楼），单级信息即可交付价值。

**Independent Test**: 进入洗衣机子层即见分组楼宇列表。

**Acceptance Scenarios**:

1. **Given** 网络可用，**When** 进入洗衣机子层，**Then** 展示至少一个分组的楼宇列表
2. **Given** 某一平台接口失败，**When** 进入洗衣机子层，**Then** 仍展示另一平台可用的楼宇；仅当全部失败时展示可读错误与"重试"
3. **Given** 未登录或演示开关开启，**When** 进入洗衣机子层，**Then** 展示内置示例数据且不发起任何网络请求

---

### User Story 2 - 查看楼层与机台状态 (Priority: P1)

用户点某楼宇，进入楼层与机台列表：每个机台展示类型（洗衣机/洗鞋机/烘干机）、名称或位置、状态（空闲/使用中/异常）；洁力机台在可得时展示剩余时间与更新时间。

**Why this priority**: "哪里有空的机器"是洗衣服务的核心价值。

**Independent Test**: 点楼宇后可看到楼层与机台列表、状态标签；洁力机台可见 ETA。

**Acceptance Scenarios**:

1. **Given** 已展示楼宇列表，**When** 点击某楼宇，**Then** 展示该楼宇的楼层与机台列表（类型 + 名称/位置 + 状态）
2. **Given** 洁力楼宇的机台状态文本包含剩余时间，**When** 展示该机台，**Then** 展示剩余时间（ETA）与更新时间
3. **Given** 状态接口失败，**When** 展示楼层/机台，**Then** 展示可读错误与"重试"
4. **Given** 该楼宇暂无数据，**When** 展示楼层/机台，**Then** 展示空态提示

---

### User Story 3 - 手动刷新与容错 (Priority: P2)

用户可手动刷新楼宇或机台数据；单平台/单接口失败不应使整体不可用。

**Why this priority**: 洗衣机状态易变（占用/释放），刷新与容错提升可用性。

**Independent Test**: 触发刷新可重新拉取；模拟单平台失败仍可见另一平台数据。

**Acceptance Scenarios**:

1. **Given** 已展示数据，**When** 触发刷新，**Then** 重新拉取并更新展示（加载中显示加载态）
2. **Given** 楼宇列表加载两平台（洁力/海乐），**When** 其一失败，**Then** 另一平台数据正常展示

---

### Edge Cases

- 单个平台接口失败：不阻塞另一平台；两平台全失败时给出可读错误与重试
- 状态接口失败但位置接口成功（或反之）：以关键数据（状态）为准，位置缺失时降级不展示位置
- 机台状态文本含未知取值：安全映射为"异常"（`error`），不导致崩溃
- 接口返回非 JSON / HTTP 非 2xx / 平台错误码：转为可读中文错误
- 演示模式（未登录或演示开关开启）：使用内置示例数据，零网络请求
- 网络不可达（如第三方接口在设备网络下不可访问）：给出可读错误与重试，不崩溃

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 必须在既有"宿舍"页内提供"洗衣机"子层入口（与电费并列/切换）；**不新增**校园主列表入口
- **FR-002**: 必须展示洗衣机楼宇的**分组**列表（洁力按 紫荆公寓/南区宿舍/双清公寓/其他位置 分组；海乐显示"海乐生活"组；仅展示有数据的组）
- **FR-003**: 必须支持点击楼宇进入其楼层与机台列表
- **FR-004**: 机台必须展示类型（洗衣机/洗鞋机/烘干机）、名称或位置、状态（空闲/使用中/异常）
- **FR-005**: 洁力机台在状态文本可得时，必须展示剩余时间（ETA）与更新时间
- **FR-006**: 楼宇列表加载必须对多平台容错：任一平台失败仍展示其它平台数据；全部失败时展示可读错误与"重试"
- **FR-007**: 楼层/机台加载失败必须展示可读错误与"重试"；无数据时展示空态
- **FR-008**: 必须提供手动刷新入口（楼宇与楼层/机台层），加载中显示加载态
- **FR-009**: 数据访问 MUST NOT 依赖校园登录会话/Cookie（第三方接口无需鉴权）；不得因未登录而不可用（演示模式除外）
- **FR-010**: 演示模式必须使用内置示例数据，**零网络请求**
- **FR-011**: 接口异常（非 JSON / HTTP 非 2xx / 平台错误码 / 结构不符）必须转为可读错误，禁止崩溃或暴露原始异常文本
- **FR-012**: 卡片与列表布局必须遵循项目约定（全宽卡片配 `constraintSize` 防右缘溢出）；新增可见文案走 i18n（中/英成对）
- **FR-013**: 除既有网络访问能力外 MUST NOT 新增权限；如确需声明网络权限，须在 `module.json5` 中声明并说明理由

### Key Entities *(include if feature involves data)*

- **洗衣平台**：洁力 / 海乐生活
- **楼宇**：标识、名称、所属平台
- **楼宇分组**：分组名、楼宇集合
- **机台**：类型（洗衣机/洗鞋机/烘干机）、名称、楼层、状态（空闲/使用中/异常）、剩余时间（分钟，可空）、更新时间（可空）、位置（可空）
- **楼层**：名称、机台集合
- **演示数据**：内置示例楼宇/楼层/机台

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 网络正常时，进入洗衣机子层 3 秒内看到楼宇分组列表
- **SC-002**: 点击楼宇后 3 秒内看到楼层与机台列表（含状态标签）
- **SC-003**: 单平台失败时仍可展示另一平台数据（容错率：至少一方可用 100%）
- **SC-004**: 演示模式下页面 100% 离线可用（零网络请求）
- **SC-005**: 接口异常或网络不可达时，100% 展示可读中文错误（无崩溃、无原始异常文本）
- **SC-006**: 机台状态映射正确（空闲/使用中/异常），洁力 ETA 与位置在可得时正确展示

## Assumptions

- 数据来源为第三方洗衣平台公开接口，**无鉴权、无 Cookie**（对齐参考实现的原生 `fetch` 用法）；经统一 HTTP 客户端直接访问
- 洁力机台的剩余时间/更新时间来自状态文本解析；海乐机台无剩余时间
- 楼宇分组规则对齐参考实现（名称含"紫荆/南区/双清"归入对应组，其余归"其他位置"；海乐楼宇仅保留含"清华"者）
- 海乐楼宇检索使用固定坐标（对齐参考实现）
- 只读特性：无预约/下单等写操作
- 复用"宿舍"页既有入口与页面约定（真实/演示双模式、错误可重试、中文 UI 文案、右上角刷新）
