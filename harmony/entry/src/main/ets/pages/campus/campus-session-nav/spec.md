# Feature Specification: 校园子功能会话自愈与跨页导航可靠性

**Created**: 2026-10-15
**Status**: Draft
**Input**: User description: "继续 ① ②：① 长时间停留后空教室/体测查询失败、刷新重试无效（需像成绩查询那样能自愈恢复）；② 冷启动后首页『查空教室』首次点击只切到校园页、第二次才进子页（需一次到位，且不破坏其它跨页导航）。"

## Overview

本特性提升校园子系统两条用户可感知链路的健壮性：
① **会话自愈**——用户长时间停留后，空教室查询与体测成绩查询因会话失效而失败时，"刷新/重试"应能自动重建会话来恢复，无需用户手动重登、也无需"先去查成绩"间接带活会话；
② **跨页导航一次到位**——冷启动后从首页快捷入口（如"查空教室""添加 DDL"）触发跨页导航时，无论目标页此刻是否已挂载，都应一次点击直达目标子页/子标签。

两项均为**缺陷修复**，目标是让既有能力表现一致、可预期；不引入新数据源、不改变既有解析与请求语义。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 长时间停留后空教室/体测查询自愈 (Priority: P1)

用户打开"空教室查询"或"体测成绩"页面后长时间停留（会话在后台失效）。当用户点击"刷新/重试"时，系统应自动重激活子系统会话、必要时重建全局会话，随后成功返回数据；用户无需手动退出重登，也不需要先去访问其它校园功能。

**Why this priority**: 这是用户直接受阻的主路径——失败后"重试无效"会让功能显得彻底不可用。

**Independent Test**: 在真实登录态下进入"空教室查询"，使子系统会话失效，点击"刷新/重试"，观察是否自动恢复并显示教室数据；"体测成绩"同理。

**Acceptance Scenarios**:

1. **Given** 用户已登录且曾成功查询过空教室，**When** 长时间停留致会话失效后点击"刷新/重试"，**Then** 系统自动恢复会话并展示最新教学楼/教室数据，无需用户手动重登。
2. **Given** 用户已登录且会话失效，**When** 在体测成绩页点击"刷新/重试"，**Then** 系统自动恢复会话并展示体测结果。
3. **Given** 空教室/体测查询首次尝试失败，**When** 系统执行恢复，**Then** 恢复过程与成绩查询链路自愈能力一致（重激活子系统会话 → 失败则重建全局会话 → 重试），全部失败才向用户报可读错误。
4. **Given** 失败原因是会话失效，**When** 触发恢复，**Then** 不得清除用户 Cookie 或已保存凭证，也不得改变对返回内容的解析口径。

---

### User Story 2 - 冷启动后"查空教室"一次到位 (Priority: P1)

冷启动（刚进入首页、校园页尚未被打开过）后，用户点击首页"查空教室"，应一次性直接进入"空教室查询"子页；不再出现"第一次只切到校园页、第二次才进子页"。

**Why this priority**: 这是首页最主要快捷入口，一次点击不通会直接损害"首页即入口"的核心体验。

**Independent Test**: 冷启动后停留在首页，直接点击"查空教室"，观察是否立即进入空教室子页。

**Acceptance Scenarios**:

1. **Given** 应用冷启动后停在首页且校园页从未被打开，**When** 用户点击"查空教室"，**Then** 系统切换到校园 Tab **并**直接打开"空教室查询"子页。
2. **Given** 校园页此时已挂载（用户此前打开过），**When** 用户点击"查空教室"，**Then** 仍直接打开"空教室查询"子页（即时导航行为不回归）。
3. **Given** 某次跨页导航目标尚未被消费，**When** 用户改为直接切换到校园 Tab（未指向任何子页），**Then** 不应再自动弹出此前遗留的子页。

---

### User Story 3 - 冷启动后"添加 DDL"直达学习·作业 (Priority: P2)

冷启动后，用户点击首页"添加 DDL"建议操作（或任何指向学习页子标签的入口），应一次性直接切换到学习页（Tab）并定位到"作业"子标签。

**Why this priority**: 与 US2 同源缺陷，属同类冷启动丢失；修复机制应统一覆盖，避免"修一半"。

**Independent Test**: 冷启动后停留在首页，点击"添加 DDL"，观察是否直接进入学习页"作业"子标签。

**Acceptance Scenarios**:

1. **Given** 应用冷启动后停在首页且学习页从未被打开，**When** 用户点击"添加 DDL"，**Then** 系统切换到学习 Tab **并**定位到"作业"子标签。
2. **Given** 目标为"通知"子标签的入口（如"未读通知"），**When** 冷启动后点击，**Then** 直接定位到"通知"子标签。

---

### User Story 4 - 既有跨页导航不回归 (Priority: P2)

修复 pending 机制与自愈能力后，其余跨页导航路径（学习页子标签、图书馆座位等 pill 入口、AI 页跳转等）行为保持与修复前一致。

**Why this priority**: 防止修复引入新的跨页导航回归。

**Independent Test**: 逐一触发既有跨页导航入口，确认目标页面/子标签与修复前一致。

**Acceptance Scenarios**:

1. **Given** 用户已登录，**When** 触发图书馆座位等既有 pill 跳转，**Then** 导航行为与修复前一致。
2. **Given** AI 页发起跨页跳转，**When** 目标页尚未挂载，**Then** 导航仍按既有契约生效。

---

### Edge Cases

- 空教室/体测失败**并非**会话失效（如返回内容解析失败、上游非 JSON）：不应被误判为会话失效而触发多余重登；应给出既有可读错误。
- 恢复过程中完整重登失败（如需二次验证/凭证失效）：应回落到首次错误并向用户展示可读提示，不静默失败、不破坏已有数据。
- 待处理导航目标在被消费前被新目标覆盖：应以最新目标为准；被消费/被覆盖后必须清除，避免下次挂载时陈旧误触发。
- 待处理导航目标生命周期为**进程内内存态**：应用被杀进程后不残留、不跨启动恢复。
- 同一时刻连续触发多个跨页导航：以最后一次为准，且不得串页。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 空教室查询链路在遭遇会话失效（系统超时页 / WebVPN 登录页等）时，系统 MUST 自愈：先尝试重新激活该子系统会话；若因门户会话缺失无法重漫游，MUST 先刷新/重建全局会话后再重漫游并重试；仅在全部失败后才向用户报可读错误。
- **FR-002**: 体测成绩查询链路 MUST 具备与 FR-001 等价的自愈能力。
- **FR-003**: 空教室/体测的"刷新/重试"入口 MUST 走与首次加载完全相同的恢复链路，不得旁路恢复能力。
- **FR-004**: 会话自愈 MUST NOT 清除用户 Cookie 或已保存凭证，且 MUST NOT 改变既有对返回内容的解析语义与请求口径。
- **FR-005**: 首页发起的跨页导航 MUST 采用"待处理导航目标"语义：当目标页此刻未挂载时，导航目标 MUST 被暂存，并在目标页挂载时被消费生效——使用户一次点击即达目标子页/子标签。
- **FR-006**: 待处理导航目标 MUST 在"被消费"或"被更新的导航目标覆盖"后被清除，避免陈旧目标在后续挂载时误触发。
- **FR-007**: 目标页已挂载时的即时导航行为 MUST 保持不变（不因引入暂存机制而退化）。
- **FR-008**: 除校园子页与学习子标签外，其它既有跨页导航路径 MUST 保持行为不变。
- **FR-009**: 空教室/体测失败提示与体测页文案 MUST 走既有国际化（中/英成对），不新增硬编码可见文案。
- **FR-010**: 待处理导航目标 MUST 仅为进程内内存态，不持久化到磁盘。

### Key Entities *(include if feature involves data)*

- **待处理导航目标（Pending Nav Target）**: 描述一次跨页导航的意图，含底部 Tab 索引与可选的"校园子页标识""学习子标签标识"；为进程内内存态，命中目标页挂载时被消费并清除。
- **子系统会话"已确保"状态**: 表示空教室/体测子系统会话是否已激活的进程内标志；会话失效恢复时需据此决定是否强制重新激活。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 会话失效后，用户仅通过页面"刷新/重试"即可恢复空教室查询，**一次重试成功率 ≥ 90%**，且**无需手动退出重登**、**无需先访问成绩查询**。
- **SC-002**: 冷启动后首页"查空教室"**首次点击直达子页成功率 100%**（修复前需两次点击）。
- **SC-003**: 冷启动后指向学习页子标签的首页入口（"添加 DDL"→作业、"未读通知"→通知）**首次点击直达对应子标签成功率 100%**。
- **SC-004**: 非会话类错误**误触发重登的比率 = 0**（即不把解析失败等误判为会话失效）。
- **SC-005**: 修复后既有跨页导航（图书馆座位 pill、AI 页跳转、学习/校园子标签）**回归失败数 = 0**。

## Assumptions

- 会话恢复能力（子系统重漫游 / 完整重登 / 强制刷新会话）为既有能力，可直接复用；空教室与体测链路当前已具备基础会话兜底，本特性补齐"漫游失败自愈"使其与成绩域一致。
- 成绩域的"漫游失败先强制刷新会话再重试"为对齐参考模式。
- 失败与重试的可见文案沿用现有国际化词条（中/英成对）。
- 待处理导航目标为内存态即可满足需求（无需跨进程/跨启动保留）。
- 修复仅限授权清单内的文件（服务层空教室/体测链路、跨页导航事件层、首页/校园页/学习页的导航消费点及其必要配合），不新增网络请求语义、不清理 Cookie。

## Open Questions

- 是否将其它校园服务（体育场馆/图书馆座位/研读间/邮件等）的"已确保"标志一并统一纳入会话复位入口？本特性默认**不含**（列为后续可选项）。
- 部分极端场景（需二次验证进入 2FA 视图、双账号 Cookie 隔离、正常退出 onDestroy 路径）因当前环境难以构造，本特性不覆盖，保留为观察项。
