# Feature Specification: 研读间查询（只读，含子系统登录）

**Created**: 2026-10-11
**Status**: Draft
**Input**: User description: "随后进行研读间相关内容推进"（经澄清：只读；日期范围近 5 天；展示我的预约；体育场馆不在本轮）

## Overview

在"场馆预约 → 研读间"接入清华大学研读间的真实数据。研读间子系统与前几个校园服务不同：它需要先完成一次**专用登录**（获取动态认证地址 → 建立研读间子系统会话 → 账号一致性校验），之后才能读取数据。本轮为**只读**：浏览研读间类型 → 近 5 天日期 → 可预约资源（房间名、人数区间、开放时间、是否开放），并展示"我的预约"记录；完整下单（选时段、邀请成员）沿用参考实现取舍，引导用户前往官方小程序完成。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 进入研读间并查看类型列表 (Priority: P1)

用户进入"场馆预约 → 研读间"，系统自动完成研读间专用登录与账号校验，随后展示研读间类型列表（类型名 + 房间数）。登录或校验失败时给出可读中文错误与重试入口。

**Why this priority**: 类型列表是所有后续浏览的入口；专用登录也是本特性唯一的新增链路，必须先打通。

**Independent Test**: 进入页面即可看到类型列表（含房间数）；在会话失效场景下可自动恢复或给出可读错误。

**Acceptance Scenarios**:

1. **Given** 已登录且会话有效，**When** 进入研读间页，**Then** 自动完成子系统登录并通过账号校验，展示类型列表（类型名 + 房间数）
2. **Given** 子系统会话失效，**When** 进入或刷新页面，**Then** 自动重建会话后重试；仍失败展示可读错误与"重试"
3. **Given** 账号校验不通过（返回账号与当前账号不一致），**When** 加载，**Then** 展示可读错误（不静默失败）

---

### User Story 2 - 查看某类型近 5 天的可预约资源 (Priority: P2)

用户展开某个研读间类型，看到"近 5 天"的日期列表；点击某一天，展示该类型当天的可预约资源列表（房间名、人数区间、开放时间、是否开放）。

**Why this priority**: 资源与开放状态是选房间的核心信息；在类型列表打通后即可交付。

**Independent Test**: 展开类型 → 点某天 → 看到资源列表（含人数区间与开放时间、开放状态徽标）。

**Acceptance Scenarios**:

1. **Given** 已展示类型列表，**When** 展开某类型，**Then** 展示近 5 天的日期项
2. **Given** 已展开某类型，**When** 点击某一天，**Then** 展示该类型当天的资源列表（房间名、人数区间、开放时间、开放/未开放标记）
3. **Given** 某天无资源或接口返回空，**When** 加载完成，**Then** 展示空态提示

---

### User Story 3 - 查看我的预约 (Priority: P3)

用户查看当前账号的研读间预约记录（房间、时间、成员）；无记录时展示空态。

**Why this priority**: 便于确认已预约的房间与时段；为只读浏览的补充信息。

**Independent Test**: 进入"我的预约"读到记录（含房间/时间/成员）；无记录时看到空态。

**Acceptance Scenarios**:

1. **Given** 存在预约，**When** 查看"我的预约"，**Then** 展示房间、时间、成员等信息
2. **Given** 无预约记录，**When** 查看"我的预约"，**Then** 展示空态提示

---

### Edge Cases

- 专用登录所需"动态认证地址"获取失败或返回异常结构时，应给出可读错误并可重试
- 子系统会话失效 / 账号校验不通过时，应自动重建会话后重试；仍失败给可读错误与重试入口
- 接口返回非 JSON，或业务错误码非 0 时，应转为可读错误（优先展示服务端消息），禁止崩溃
- 某类型在某天无资源时展示空态，不阻塞其他类型/日期
- 演示模式（未登录或演示开关开启）下使用内置示例数据，不发起任何网络请求
- 用户尝试预约时：仅给出"完整下单请在官方小程序完成"的提示（本阶段不迁移写操作）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: "场馆预约"入口必须能进入"研读间"页（只读）；体育场馆入口保持后续增量
- **FR-002**: 加载数据前必须完成研读间子系统登录：获取动态认证地址 → 建立子系统会话 → 校验返回账号与当前账号一致；任一步失败必须给出可读错误
- **FR-003**: 必须展示研读间类型列表（类型名 + 房间数）
- **FR-004**: 必须支持展开某类型并展示"近 5 天"日期项
- **FR-005**: 必须支持选择某天并展示该类型当天的资源列表（房间名、人数区间、开放时间、开放/未开放标记）
- **FR-006**: 必须展示"我的预约"（房间、时间、成员）；无记录时展示空态
- **FR-007**: 子系统会话失效时必须自动重建会话并重试；失败时展示可读错误与"重试"入口
- **FR-008**: 演示模式必须使用内置示例数据且不发起网络请求
- **FR-009**: 接口异常（非 JSON / 业务错误码非 0 / 结构不符）必须转为可读错误，禁止崩溃或暴露原始异常文本
- **FR-010**: 页面必须提供手动刷新入口（右上角），并在加载中显示加载态
- **FR-011**: 必须给出只读引导（"完整下单请在官方小程序完成"）
- **FR-012**: 卡片与列表布局必须遵循项目约定（全宽卡片配 `constraintSize` 防右缘溢出）

### Key Entities *(include if feature involves data)*

- **研读间类型**：类型标识、类型名、房间数、下属房间（房间标识、名称、最短预约时长）
- **研读间资源**：房间标识/名称、类型、所属实验室/房间、预约规则（次数上限、最短/最长时长、取消时限）、人数区间（最少/最多）、开放起止时间、当前占用情况
- **预约记录**：标识、房间名、类型名、日期、起止时间、预约人、成员列表
- **账号校验信息**：账号标识（用于与当前登录账号比对）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 已登录用户进入研读间页，在网络正常时 5 秒内看到类型列表（含一次子系统登录）
- **SC-002**: 选择某类型某天后，资源列表在 3 秒内呈现
- **SC-003**: "我的预约"在 3 秒内可读（有记录显示列表，无记录显示空态）
- **SC-004**: 子系统会话失效场景下，用户无需手动重新登录即可在自动恢复后看到数据（恢复成功率 ≥ 90%）
- **SC-004**: 从类型列表到某天资源 ≤ 2 次点击可达
- **SC-005**: 演示模式下页面 100% 离线可用（零网络请求）
- **SC-006**: 接口异常或会话不可恢复时，100% 展示可读中文错误（无崩溃、无原始异常文本）

## Assumptions

- **只读范围**：预约与取消**不迁移**（对齐参考实现"完整下单走官方小程序"）；UI 给出引导提示
- 研读间专用登录的"动态认证地址"需跟随重定向获取最终地址以解析登录标识；该标识经**既有 id 漫游链路**建立子系统会话（无需新的漫游机制），随后以用户信息接口校验账号一致性
- 日期范围固定"近 5 天"（对齐参考实现）
- 研读间接口为 JSON（含业务错误码与消息字段；错误码非 0 视为失败）
- 复用现有统一认证与 WebVPN 会话；复用现有"场馆预约"入口页并**内联渲染**研读间组件（与图书馆座位一致，不新增校园页分发项）
- 沿用现有页面约定：真实/演示双模式、错误可重试、中文 UI 文案、右上角刷新
- **体育场馆**不在本轮范围

## Open Questions

- 资源条目是否需要展示当日占用明细（已预约时段列表）
- "我的预约"是否需要展示完整成员名单（超出一定人数时如何折叠）
- 类型/资源的名称是否需要在"暂未开放"等特殊标记下特殊展示（如置灰）
