# Feature Specification: 体育场馆查询（只读）

**Created**: 2026-10-11
**Status**: Draft
**Input**: User description: "继续体育场馆预约"（经澄清：只读；日期范围近 7 天；预约记录合并单一列表）

## Overview

在"场馆预约 → 体育场馆"接入清华大学体育场馆的真实数据（只读）：浏览**固定场馆清单**（默认选中第一个）→ **近 7 天**日期 → 该场馆当日**资源**（时段、场地、费用、是否可预约、是否已锁定/已被预约）与**限额/联系电话**，并展示"我的预约记录"合并列表（未支付与已支付；含可取消/可支付标记，但本轮不执行任何写操作）。下单、支付与退订沿用官方渠道，页面给出引导提示。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看场馆某日的可预约资源 (Priority: P1)

用户进入"场馆预约 → 体育场馆"，选择某场馆与近 7 天中的某一天，看到该场馆当日的资源列表：时段、场地、费用、是否可预约、是否已被锁定/预约。

**Why this priority**: 场地与时段是否可约是最高频诉求，单场馆单日即可交付价值。

**Independent Test**: 进入页面即见默认场馆当日资源列表；切换日期/场馆后列表随之刷新。

**Acceptance Scenarios**:

1. **Given** 已登录且会话有效，**When** 进入体育场馆页，**Then** 展示固定场馆清单（默认选中第一个）与"近 7 天"日期项（默认今天），并展示当日资源列表（时段、场地、费用、可预约/已锁定状态）
2. **Given** 已展示资源，**When** 切换到另一天或另一场馆，**Then** 资源列表按所选场馆/日期刷新
3. **Given** 会话失效，**When** 进入页面，**Then** 自动恢复会话后重试；仍失败展示可读错误与"重试"

---

### User Story 2 - 查看场馆限额与联系电话 (Priority: P2)

用户看到所选场馆当日的预约限额（已用/上限）以及联系电话（服务端提供时）。

**Why this priority**: 限额决定"还能不能约"，电话便于现场咨询；为资源列表的补充信息。

**Independent Test**: 加载完成即看到限额数值；服务端提供电话时看到电话号码。

**Acceptance Scenarios**:

1. **Given** 资源加载成功，**When** 页面呈现，**Then** 展示当日限额（已用/上限）
2. **Given** 服务端返回联系电话，**When** 页面呈现，**Then** 展示该电话；未返回时不展示该行

---

### User Story 3 - 查看我的预约记录 (Priority: P3)

用户查看当前账号的体育场馆预约记录（合并未支付与已支付）：名称、场地、时间、价格、支付方式，并标注是否可取消、是否有可支付动作。

**Why this priority**: 便于确认订单与待支付项；为只读浏览的补充信息。

**Independent Test**: 进入"我的预约记录"读到合并列表；无记录时看到空态。

**Acceptance Scenarios**:

1. **Given** 存在预约/订单，**When** 查看记录，**Then** 展示合并列表（名称/场地/时间/价格/支付方式），并标注可取消或可支付
2. **Given** 无记录，**When** 查看记录，**Then** 展示空态提示

---

### Edge Cases

- 子系统会话失效 / 返回登录页标记时，应自动恢复（重漫游体育场馆子系统）后重试；失败展示可读错误与重试入口
- 资源页面结构异常（缺少限额变量或脚本片段）时，应转为可读错误而非崩溃
- 某场馆某日无资源时展示空态，不阻塞其他场馆/日期
- 页面为 GBK 编码（中文须正确解码，不得出现乱码）
- 演示模式（未登录或演示开关开启）下使用内置示例数据，不发起任何网络请求
- 用户尝试下单/支付时：仅给出"下单与支付请通过官方渠道完成"的提示（本阶段不迁移写操作）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: "场馆预约"入口必须能进入"体育场馆"页（只读）
- **FR-002**: 必须展示固定场馆清单（对齐参考实现的场馆集合）并支持选择，默认选中第一个
- **FR-003**: 必须支持"近 7 天"日期选择，默认今天
- **FR-004**: 必须展示所选场馆当日的预约限额（已用/上限）
- **FR-005**: 服务端提供联系电话时必须展示该电话；未提供时不展示
- **FR-006**: 必须展示所选场馆当日的资源列表：时段、场地、费用（有值时）、是否可预约、是否已锁定/已被预约
- **FR-007**: 必须展示"我的预约记录"合并列表（名称、场地、时间、价格、支付方式），并标注可取消与可支付（本轮仅展示，不提供操作）；无记录时展示空态
- **FR-008**: 会话失效时必须自动恢复（重漫游体育场馆子系统）并重试；失败时展示可读错误与"重试"入口
- **FR-009**: 演示模式必须使用内置示例数据且不发起网络请求
- **FR-010**: 接口异常（结构不符 / 限额变量缺失 / 非预期响应）必须转为可读错误，禁止崩溃或暴露原始异常文本
- **FR-011**: 页面为 GBK 编码时，中文内容必须正确解码（无乱码）
- **FR-012**: 页面必须提供手动刷新入口（右上角），并在加载中显示加载态
- **FR-013**: 必须给出只读引导（"下单与支付请通过官方渠道完成"）
- **FR-014**: 卡片与列表布局必须遵循项目约定（全宽卡片配 `constraintSize` 防右缘溢出）

### Key Entities *(include if feature involves data)*

- **体育场馆**：名称、场馆标识、项目标识（固定清单）
- **场馆资源**：资源标识、资源校验值、时段、场地名、叠加人数、是否可网上预约、费用、预约标识、是否锁定、用户类型、支付状态
- **资源总量信息**：已用数、上限数、联系电话
- **预约记录**：名称、场地、时间、价格、支付方式、预约标识（可取消）、支付标识（可支付）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 已登录用户进入体育场馆页，在网络正常时 3 秒内看到默认场馆当日限额与资源列表
- **SC-002**: 切换场馆或日期后，资源列表在 3 秒内刷新
- **SC-003**: "我的预约记录"在 3 秒内可读（有记录显示列表，无记录显示空态）
- **SC-004**: 会话失效场景下，用户无需手动重新登录即可在自动恢复后看到数据（恢复成功率 ≥ 90%）
- **SC-005**: 演示模式下页面 100% 离线可用（零网络请求）
- **SC-006**: 接口异常或会话不可恢复时，100% 展示可读中文错误（无崩溃、无原始异常文本）
- **SC-007**: 中文内容 0 乱码（GBK 正确解码）
- **SC-008**: 从场馆列表到当日资源 ≤ 2 次点击可达

## Assumptions

- **只读范围**：下单、支付与退订**不迁移**（页面给出官方渠道引导）
- 场馆为**固定清单**（对齐参考实现的 8 个场馆），不提供自定义场馆/项目标识
- 日期范围固定"近 7 天"（今天起偏移 0–6 天）
- 体育场馆接口为 **GBK 编码的 HTML**，资源与限额以页面脚本变量/函数调用形式给出（非 JSON）；沿用现有字符集推断机制，必要时补充按 URL 的编码标记
- 子系统会话经"通用漫游"（体育场馆子系统标识）激活——复用项目现有漫游能力
- 复用现有统一认证与 WebVPN 会话；复用"场馆预约"入口页并**内联渲染**体育场馆组件（与图书馆座位/研读间一致，不新增校园页分发项）
- 资源列表按参考实现的语义过滤展示（可网上预约且未被锁定的视为可约；其余按状态标注）
- 沿用现有页面约定：真实/演示双模式、错误可重试、中文 UI 文案、右上角刷新

## Open Questions

- "叠加人数"是否需要在资源卡片上展示
- 预约记录的排序依据（接口顺序 / 时间倒序）
- 限额为 0 时是否需要额外引导（如提示"今日已约满"）
