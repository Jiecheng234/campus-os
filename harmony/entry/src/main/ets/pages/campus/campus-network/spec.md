# Feature Specification: 校园网接入（网络信息查询、设备注销与验证码登录）

**Created**: 2026-10-11
**Status**: Draft
**Input**: User description: "继续进行校园网/场馆预约接入"（经澄清：本轮仅校园网；场馆预约作为独立特性后续推进，仅覆盖图书馆座位 + 研读间）

**修订记录**: 2026-10-11 — 真实登录后实测发现校园网自助服务要求图形验证码；参考项目会**页内主动展示图片验证码，填写后成功载入数据**。据此修改 FR-006（原"不接入验证码登录"），新增 US5 图片验证码登录及 FR-010～FR-014。

## Overview

为校园页"校园网络"子页接入清华大学校园网自助服务的真实数据：展示账户余额与用量、账户信息、在线设备列表，支持注销指定在线设备，并在服务端要求图形验证码时提供**页内验证码登录**（图片 + 输入 + 提交 + 换一张），登录成功后自动载入数据。未登录或演示模式时保持内置示例数据。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看校园网账户余额与用量 (Priority: P1)

已登录用户进入"校园 → 校园网络"，在页面顶部直接看到当前网络账户的余额、本月已用流量/时长与结算日期。

**Why this priority**: 余额与用量是最高频诉求（是否欠费、是否接近限额），单卡即可交付价值。

**Independent Test**: 打开页面即可看到余额卡数值，无需任何交互，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 已登录且会话有效，**When** 进入校园网络页，**Then** 顶部展示产品名、已用流量、已用时长、账户余额、结算日期
2. **Given** 会话失效，**When** 进入页面，**Then** 自动恢复会话后重试；仍失败时展示可读错误与"重试"

---

### User Story 5 - 图片验证码登录后载入数据 (Priority: P2)

当服务端要求图形验证码时，页面直接展示验证码图片与输入框；用户填写验证码并提交，登录成功后页面自动载入余额、账户信息与在线设备。

**Why this priority**: 真实模式下自助服务常要求验证码，本能力是"真实数据可见"的前置条件（对齐参考项目"进入页面即主动展示验证码"的行为）；为保持故事 ID 与既有验证记录的可追溯性，ID 顺序不重排，故以 Priority 表达其仅次于 P1 的地位。

**Independent Test**: 在需要验证码的环境中打开页面，应直接看到验证码图片；填入正确验证码提交后，页面自动出现真实余额/账户/设备数据。

**Acceptance Scenarios**:

1. **Given** 服务端要求验证码，**When** 进入页面，**Then** 页内展示验证码图片、输入框、"提交"与"换一张"，并给出简短说明
2. **Given** 已展示验证码，**When** 点击"换一张"，**Then** 图片刷新为新的验证码
3. **Given** 已输入验证码，**When** 提交且校验通过，**Then** 自动重载并展示余额/账户/设备数据，验证码区块消失
4. **Given** 提交的验证码错误或已过期，**When** 提交，**Then** 给出可读错误提示并**自动换新一张**验证码，输入框清空

---

### User Story 2 - 查看校园网账户信息 (Priority: P3)

用户查看账户资料：用户名、联系邮箱、联系电话、固定电话、真实姓名、用户组、状态、所在位置、允许在线设备数。

**Why this priority**: 账户资料用于核对账号归属与联系方式，重要性次于余额与登录前置能力。

**Independent Test**: 加载完成即可读到各字段，空值以占位符呈现（如"—"）。

**Acceptance Scenarios**:

1. **Given** 会话有效，**When** 页面加载完成，**Then** 展示上述字段；缺失字段以占位符呈现

---

### User Story 3 - 查看在线设备列表 (Priority: P4)

用户查看当前在线的设备（IPv4、IPv6、登录时间、权限、MAC）。

**Why this priority**: 设备列表是管理在线终端的基础，为注销操作提供目标。

**Independent Test**: 加载完成即可看到设备逐条明细；无设备时显示空态。

**Acceptance Scenarios**:

1. **Given** 存在在线设备，**When** 加载完成，**Then** 逐条展示 5 个字段
2. **Given** 无在线设备，**When** 加载完成，**Then** 展示空态提示

---

### User Story 4 - 注销在线设备 (Priority: P5)

用户对某台在线设备执行"注销"，需二次确认；成功后列表刷新并提示，失败展示服务端原因。

**Why this priority**: 设备数接近上限或发现陌生设备时需要自助下线；为唯一写操作，风险可控且需确认。

**Independent Test**: 对任一在线设备执行注销，观察确认弹窗、结果提示与列表变化。

**Acceptance Scenarios**:

1. **Given** 存在在线设备，**When** 点击"注销"，**Then** 弹出二次确认；取消则无任何变化
2. **Given** 用户在确认框点击确定，**When** 服务端返回成功，**Then** 提示"设备已注销"且列表刷新
3. **Given** 用户在确认框点击确定，**When** 服务端返回失败，**Then** 展示服务端失败原因

---

### Edge Cases

- 会话失效 / 返回统一登录页时，应自动恢复会话后重试；两次恢复仍失败则展示可读错误与重试入口
- 服务端要求验证码时进入页内验证码登录态（见 US5）；验证码图片获取失败时给出可读错误与"换一张"
- 验证码登录所需参数（CSRF / 公开密钥）缺失时，提示"登录页缺少必要参数，请刷新后重试"
- 登录账号名解析失败时，给出可读错误（不进入静默失败）
- 余额表 / 设备表结构异常（缺少列）时，应转为可读错误而非崩溃
- 演示模式（未登录或演示开关开启）下使用内置示例数据，不发起任何网络请求
- 注销操作缺少必要令牌时，应给出可读错误

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 真实模式下，"校园网络"页必须展示账户余额卡：产品名、已用流量、已用时长、账户余额、结算日期
- **FR-002**: 必须展示账户信息：用户名、联系邮箱、联系电话、固定电话、真实姓名、用户组、状态、所在位置、允许在线设备数
- **FR-003**: 必须展示在线设备列表（IPv4、IPv6、登录时间、权限、MAC）；无设备时展示空态
- **FR-004**: 必须支持对单台在线设备执行注销，操作前二次确认；成功时提示并刷新列表，失败时展示服务端原因
- **FR-005**: 会话失效时必须自动恢复（重漫游 / 重登录）并重试；恢复失败时展示可读错误与"重试"入口
- **FR-006**: 服务端要求验证码时，必须进入**页内验证码登录态**：展示验证码图片、输入框、"提交"与"换一张"；提交成功后自动重载数据（替代原"仅提示走网页端"的方案）
- **FR-007**: 演示模式（未登录或演示开关开启）必须使用内置示例数据且不发起网络请求
- **FR-008**: 响应结构异常时必须转为可读错误，禁止崩溃或暴露原始异常文本
- **FR-009**: 页面必须提供手动刷新入口，并在加载中显示加载态
- **FR-010**: 必须能获取并展示图形验证码图片；"换一张"必须能刷新为新的验证码
- **FR-011**: 提交验证码时必须先解析登录页必要参数（CSRF 令牌与公开密钥），并对密码做加密后提交（加密方式与参考项目一致）
- **FR-012**: 验证码登录的用户名必须取"校园网自助服务对应的账号名"（通过漫游信息门户解析获得，对齐参考实现）；解析失败时必须给出可读错误
- **FR-013**: 验证码提交失败（错误 / 过期）时必须给出可读提示并**自动刷新验证码**，同时清空输入
- **FR-014**: 验证码登录成功后必须自动重载快照数据（余额 / 账户 / 设备），使 US1–US3 立即可见

### Key Entities *(include if feature involves data)*

- **网络账户余额**: 产品名、已用字节数、已用时长、账户余额、结算日期
- **网络账户信息**: 用户名、邮箱、电话、固话、真实姓名、用户组、状态、位置、允许设备数
- **在线设备**: 设备标识、IPv4、IPv6、登录时间、权限、MAC
- **验证码登录表单**: CSRF 令牌、加密后的密码、验证码输入、账号名、（可选的短信码占位）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 已登录用户打开校园网络页，在网络正常时 3 秒内看到余额 / 账户 / 在线设备
- **SC-002**: 会话失效场景下，用户无需手动重新登录，自动恢复后可看到数据（恢复成功率 ≥ 90%）
- **SC-003**: 注销设备成功后，列表在 2 秒内反映最新在线设备
- **SC-004**: 演示模式下页面 100% 离线可用（零网络请求）
- **SC-005**: 结构异常或会话不可恢复时，100% 展示可读中文错误（无崩溃、无原始异常文本）
- **SC-006**: 需要验证码时，页面进入验证码态 ≤ 3 秒；提交正确验证码后 5 秒内展示真实数据
- **SC-007**: 验证码提交失败时，100% 自动换新图且给出中文提示（无需用户手动操作）

## Assumptions

- 复用现有统一身份认证与 WebVPN 会话（校园网经同一 WebVPN 域访问），无需独立漫游；会话恢复沿用现有"两层恢复"机制
- 验证码登录的用户名取邮箱账号名（漫游信息门户用户信息页解析）——对齐参考实现，以降低账号不匹配风险
- 密码加密采用登录页提供的公开密钥（对齐参考项目所用库的默认填充方式，即 PKCS#1 v1.5）
- 校园网充值仍不在本阶段范围
- 唯一非登录类写操作为设备注销，且必须经用户确认
- 页面解析沿用参考实现的 HTML 结构（余额表 / 账户表 / 设备表 / 登录表单）
- 沿用现有页面约定：真实 / 演示双模式、错误可重试、中文 UI 文案、右上角刷新

## Open Questions

- 在线设备"权限"字段是否需要中文映射（当前按服务端原样文本展示）
- 是否保留"充值"入口（本阶段不迁移充值，仅以提示引导网页端）？
- 允许在线设备数接近上限时是否需要额外引导（当前仅展示数值）
