# Feature Specification: 图书馆座位查询与预约（含取消与首页直达）

**Created**: 2026-10-11
**Updated**: 2026-10-16
**Status**: Draft
**Input**: 原描述："继续进行校园网/场馆预约接入"（本轮 = 图书馆座位只读多级浏览 + 我的预约）。
**Update Input**（2026-10-16）："接入图书馆座位预定并连接首页跳转"——在既有只读页上补齐**预约**与**取消**写操作，并将首页"图书馆座位"入口接通为一次到位直达座位页（经澄清：写操作范围 = 预约 + 取消；首页跳转落点 = 直达座位页；提交交互 = 二次确认；spec 产物沿用本目录）。
**Revision**：2026-10-11 初版（只读）；2026-10-16 合并预约/取消/首页直达（新增 US4–US6、FR-014~020、SC-008~011；移除"写操作不迁移"的只读边界）。

## Overview

在"校园 → 场馆预约 → 图书馆座位"内接入清华大学图书馆座位的真实数据：浏览"馆 → 楼层（使用率）→ 区域（可用数）→ 座位（状态）"多级结构，支持"今天/明天"切换，并展示当前账号的座位预约记录。本轮在既有**只读**能力之上补齐**预约座位**与**取消预约**写操作（均带二次确认），并让首页"图书馆座位"入口一次点击直接进入座位页（不再提示"即将接入"）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 浏览图书馆与楼层使用率 (Priority: P1)

用户进入"场馆预约 → 图书馆座位"，看到图书馆列表（默认选中开放的馆），以及该馆在所选日期（今天/明天）下各楼层的使用率（可用/总数）；可切换"今天/明天"刷新楼层数据。

**Why this priority**: 楼层使用率是最高频诉求（选哪里自习），单级信息即可交付价值。

**Independent Test**: 进入页面即见馆与楼层使用率；切换"明天"后楼层使用率随之刷新。

**Acceptance Scenarios**:

1. **Given** 已登录且会话有效，**When** 进入图书馆座位页，**Then** 展示馆列表并默认选中一个开放的馆，同时展示该馆楼层列表及各楼层"可用/总数"
2. **Given** 已展示楼层，**When** 切换为"明天"，**Then** 楼层使用率按明天数据刷新
3. **Given** 会话失效，**When** 进入页面，**Then** 自动恢复会话后重试；仍失败展示可读错误与"重试"

---

### User Story 2 - 查看区域与座位状态 (Priority: P2)

用户点某个楼层，进入区域列表（各区域可用/总数/已预约数）；再点某个区域，进入座位列表，看到座位名称与状态（可用 / 已预约 / 已被占用 / 不可用）。

**Why this priority**: 在选定楼层后进一步定位具体座位，是自习选座的必要信息。

**Independent Test**: 从楼层点入区域、再点入座位，均可看到对应列表与状态；逐级可返回。

**Acceptance Scenarios**:

1. **Given** 已展示楼层列表，**When** 点击某开放楼层，**Then** 展示该楼层的区域列表（含各区域可用/总数/已预约数）
2. **Given** 已展示区域列表，**When** 点击某区域，**Then** 展示该区域座位列表（座位名 + 状态标签）
3. **Given** 处于区域或座位层级，**When** 触发返回（页面返回按钮或系统返回），**Then** 逐级回到上一层（座位 → 区域 → 楼层 → 馆）

---

### User Story 3 - 查看我的预约 (Priority: P3)

用户查看当前账号的图书馆座位预约记录（座位、时间、状态）；无记录时展示空态提示。

**Why this priority**: 便于确认自己的预约是否生效/何时到期；也是取消预约（US5）的入口。

**Independent Test**: 进入"我的预约"即可读到记录列表；无记录时看到空态。

**Acceptance Scenarios**:

1. **Given** 已登录且存在预约，**When** 查看"我的预约"，**Then** 逐条展示座位、时间、状态
2. **Given** 无预约记录，**When** 查看"我的预约"，**Then** 展示空态提示

---

### User Story 4 - 预约座位 (Priority: P1)

用户在座位列表中对"可用"座位发起预约：点击后弹出确认（馆/楼层/区域/座位/日期/时段），确认后提交；成功时给出成功提示并刷新"我的预约"。

**Why this priority**: 预约是本次接入的核心新价值（把"只读查询 + 跳小程序下单"变为应用内可下单）。

**Independent Test**: 对可用座位点击"预约"，在确认框确认后，可看到成功提示，且"我的预约"出现该记录。

**Acceptance Scenarios**:

1. **Given** 已登录、会话有效、处于某区域座位列表且该座位"可用"，**When** 点击该座位并确认预约，**Then** 提交成功并提示，且"我的预约"刷新出现该记录
2. **Given** 座位"已预约/已被占用/不可用"，**When** 查看该座位，**Then** 不提供"预约"操作（或以禁用态呈现）
3. **Given** 预约提交需要访问令牌，**When** 令牌缺失/过期，**Then** 自动刷新令牌并重试一次；仍失败给出可读错误
4. **Given** 演示模式（未登录或演示开关开启），**When** 尝试预约，**Then** 不发起网络请求，给出可读提示

---

### User Story 5 - 取消预约 (Priority: P2)

用户在"我的预约"中对可取消的记录发起取消：点击后弹出确认，确认后提交；成功时提示并刷新记录列表。

**Why this priority**: 与预约配套，避免用户必须去官方小程序才能取消。

**Independent Test**: 在"我的预约"点某记录的"取消"，确认后可看到成功提示，且该记录状态/列表随之更新。

**Acceptance Scenarios**:

1. **Given** 已登录且"我的预约"存在可取消记录，**When** 点击取消并确认，**Then** 提交成功并提示，列表刷新
2. **Given** 记录不可取消（如已使用/已取消），**When** 查看该记录，**Then** 不提供"取消"操作（或以禁用态呈现）
3. **Given** 取消需要访问令牌，**When** 令牌缺失/过期，**Then** 自动刷新令牌并重试一次；仍失败给出可读错误

---

### User Story 6 - 首页直达座位页 (Priority: P3)

用户在首页点击"图书馆座位"入口，应一次点击直接进入图书馆座位页（而非停留首页或提示"即将接入"）。

**Why this priority**: 提升可发现性；为小的接线改动（复用既有跨页导航机制）。

**Independent Test**: 冷启动后停留在首页，点击"图书馆座位"，一次点击即进入座位页。

**Acceptance Scenarios**:

1. **Given** 冷启动后停在首页且场馆预约页从未打开，**When** 点击"图书馆座位"，**Then** 一次点击进入图书馆座位页
2. **Given** 首页入口被点击，**When** 页面切换完成，**Then** 不再出现"即将接入"提示
3. **Given** 既有其它跨页导航（查空教室、添加 DDL 等），**When** 使用它们，**Then** 行为不受本改动影响

---

### Edge Cases

- 会话失效 / 子系统会话过期时，应自动恢复（重漫游图书馆座院子系统或完整重登录）后重试；恢复失败展示可读错误与重试入口（读与写均适用）
- 访问令牌（access_token）缺失、过期或接口提示令牌失效时，应自动刷新后重试一次；再失败转为可读错误
- 接口返回非 JSON，或缺少列表/状态字段时，应转为可读错误而非崩溃
- 未开放（无效）的楼层应标记且**不发起**后续请求（避免无谓失败）
- 单个楼层聚合使用率失败时，不应阻塞其他楼层的展示
- 演示模式（未登录或演示开关开启）下使用内置示例数据，**读写均不发起任何网络请求**；写操作给出可读提示
- 预约时若座位已被他人占用/时段已失效：提交失败应转为可读错误并刷新座位状态
- 预约/取消提交中应避免重复提交（按钮禁用/加载态）
- 写操作日志与错误信息中不得出现访问令牌等凭据明文

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: "场馆预约"入口必须能进入"图书馆座位"页；研读间/体育场馆入口保持各自增量（可提示"即将支持"）
- **FR-002**: 必须展示图书馆列表，并默认选中一个开放的馆
- **FR-003**: 必须支持"今天/明天"日期切换，并据此刷新楼层与座位数据
- **FR-004**: 必须展示所选馆的楼层列表及各楼层可用/总数（使用率）；未开放楼层应标记且不请求其明细
- **FR-005**: 必须支持点击楼层进入区域列表，展示各区域可用/总数/已预约数
- **FR-006**: 必须支持点击区域进入座位列表，展示座位名称与状态（可用 / 已预约 / 已被占用 / 不可用）
- **FR-007**: 必须支持"馆 → 楼层 → 区域 → 座位"的页内多级导航，并可逐级返回（含系统返回键语义）
- **FR-008**: 必须展示"我的预约"（座位、时间、状态）；无记录时展示空态
- **FR-009**: 会话失效时必须自动恢复并重试；恢复失败时展示可读错误与"重试"入口
- **FR-010**: 演示模式必须使用内置示例数据；**读与写均不发起网络请求**
- **FR-011**: 接口异常（非 JSON / 缺少字段 / 结构不符）必须转为可读错误，禁止崩溃或暴露原始异常文本
- **FR-012**: 页面必须提供手动刷新入口（右上角），并在加载中显示加载态
- **FR-013**: 卡片与列表布局必须遵循项目约定（全宽卡片配 `constraintSize` 防右缘溢出）
- **FR-014**: 必须支持对"可用"座位发起预约；提交前必须二次确认（展示馆/楼层/区域/座位/日期/时段）；"已预约/已被占用/不可用"座位不提供预约操作
- **FR-015**: 预约与取消请求必须携带有效访问令牌（自图书馆主页抓取并做短时缓存）；令牌缺失/过期/失效时自动刷新并重试一次
- **FR-016**: 必须支持对"我的预约"中可取消的记录发起取消；提交前必须二次确认；不可取消的记录不提供取消操作
- **FR-017**: 预约/取消成功后必须刷新"我的预约"（及必要时座位状态）并给出结果提示；失败必须给出可读原因
- **FR-018**: 首页"图书馆座位"入口必须一次点击直达座位页（复用既有待处理导航目标机制），且不再出现"即将接入"提示
- **FR-019**: 写操作（预约/取消）相关的日志与错误信息不得包含访问令牌等凭据明文
- **FR-020**: 写操作提交中必须避免重复提交（禁用/加载态），防止重复下单

### Key Entities *(include if feature involves data)*

- **图书馆**：标识、中英文名、是否开放
- **楼层**：标识、所属馆、中英文名、是否开放、可用数、总数（由下属区域聚合）
- **区域**：标识、中英文名、是否开放、可用数、总数、已预约数
- **座位**：标识、名称、状态（可用/已预约/已被占用/不可用）、类型
- **预约记录**：标识、座位位置、时间、状态、可取消标识（用于取消请求）
- **预约时段（segment）**：区域在目标日期的时段标识与起止时间
- **访问令牌（access_token）**：写操作所需令牌（短时缓存，禁止明文落日志）
- **日期选择**：今天 / 明天

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 已登录用户进入图书馆座位页，在网络正常时 3 秒内看到馆列表与楼层使用率
- **SC-002**: 切换"今天/明天"后，楼层使用率在 3 秒内刷新为新日期数据
- **SC-003**: 从馆列表到具体座位 ≤ 3 次点击可达，且任一层级可逐级返回
- **SC-004**: "我的预约"在 3 秒内可读（有记录显示列表，无记录显示空态）
- **SC-005**: 会话失效场景下，用户无需手动重新登录即可在自动恢复后看到数据（恢复成功率 ≥ 90%）
- **SC-006**: 演示模式下页面 100% 离线可用（零网络请求）
- **SC-007**: 接口异常或会话不可恢复时，100% 展示可读中文错误（无崩溃、无原始异常文本）
- **SC-008**: 对可用座位的预约，在二次确认后**一次提交成功率 ≥ 90%**（令牌过期场景由自动刷新覆盖），成功后"我的预约"立即可见该记录
- **SC-009**: 对可取消记录的取消，在二次确认后**一次提交成功率 ≥ 90%**，列表随之更新
- **SC-010**: 首页"图书馆座位"入口**首次点击直达座位页成功率 100%**（不再出现第二次点击或"即将接入"）
- **SC-011**: 令牌过期场景下，写操作**无需用户干预**即可自愈（自动刷新重试），用户可感知失败率 = 0

## Assumptions

- 写操作对齐参考实现：预约 `POST api.php/spaces/{seatId}/book`（body：access_token、userid、segment、type、operateChannel=2）；取消 `POST api.php/profile/books/{bookingId}`（_method=delete）；令牌自图书馆主页 HTML 抓取并缓存约 5 分钟
- 复用现有统一认证与 WebVPN 会话；图书馆座院子系统经"id 漫游"激活（既有能力），写操作复用既有两层会话兜底
- 图书馆接口为 JSON：响应含失败标记（status）与字段；非 JSON 视为异常
- **研读间**（需 cab 登录）与**体育场馆**不在本轮范围，作为后续独立增量
- 沿用现有入口壳（"场馆预约"页）与页面约定：真实/演示双模式、错误可重试、中文 UI 文案、右上角刷新
- 日期语义仅"今天/明天"（与参考实现一致），不提供自定义日期；预约时段取自既有"目标日时段"解析
- 演示模式下写操作以提示代替真实提交（不发起请求）

## Open Questions

- 座位状态的数值映射是否需更细粒度中文标签（当前：可用 / 已预约 / 已被占用 / 不可用）
- 预约确认框是否需展示该区域当前预约时段起止（当前按既有"目标日时段"信息展示）
- "我的预约"是否需要展示历史（已取消/已过期）记录（当前按接口返回展示）
