**Created**: 2026-10-16
**Status**: Draft

## Overview

在既有 AI 聊天能力（provider 配置 + 流式对话）之上接入 **agent（工具调用）**：模型依据用户意图调用校园工具集（**只读 38 + 可逆写 11**），读取真实数据或执行可逆写操作；写操作必须经"**dry-run 预览 → 用户二次确认 → 执行 → 执行后验证**"并写入**审计**。不可逆写（选课/退课）本期**不接入**。工具轨迹与结果在对话中可见，敏感信息脱敏；演示模式不发起真实网络/写操作。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 只读工具问答 (Priority: P1)

用户用自然语言询问校园信息（天气、今日概览、作业、成绩、电费、洗衣机、校园卡、校园网、体育场馆、空教室、图书馆座位/研读间、资讯、邮件等），系统调用相应**只读工具**获取真实数据并给出回答。

**Why this priority**: 只读工具是 agent 的基础价值（把聊天变为"能查真实数据"）。

**Independent Test**: 询问"今天天气/我的作业/电费余额/哪有空教室"，系统调用对应只读工具并给出基于真实数据的结果。

**Acceptance Scenarios**:

1. **Given** 已配置可用 provider 且处于真实模式，**When** 用户询问某只读信息，**Then** 系统调用对应只读工具、回灌结果并给出答案（无需用户额外操作）
2. **Given** 一次回答需要多个工具（如"今日概览"），**When** 模型连续发起工具调用，**Then** 系统按轮次执行并最终给出综合答案（受轮数上限约束）
3. **Given** 工具执行失败（会话失效/接口异常），**When** 调用该工具，**Then** 失败以可读结果回灌模型并继续对话（不中断会话）

---

### User Story 2 - 可逆写操作（预览 + 二次确认 + 验证 + 审计） (Priority: P1)

用户请求写操作（如预约/取消图书馆座位、预约/取消研读间、注销校园网设备、增删个人日程/DDL、记住偏好），系统先给出**预览**，用户**二次确认**后方执行，执行后**验证**结果并记录**审计**。

**Why this priority**: 写操作有真实后果，必须"可控 + 可追溯"，是 agent 可用性的安全底线。

**Independent Test**: 请求"预约某座位"，系统展示预览并等待确认；确认后执行并验证；拒绝则不执行。

**Acceptance Scenarios**:

1. **Given** 用户请求可逆写操作，**When** 模型发起该工具调用，**Then** 系统展示预览（影响对象/关键参数/是否可逆）并**等待用户确认**，未确认不执行
2. **Given** 用户确认，**When** 执行，**Then** 提交成功并**执行后验证**（如在记录中确认存在）；成功后写入审计
3. **Given** 用户取消确认，**When** 返回对话，**Then** 不执行任何写操作，并给出"已取消"反馈
4. **Given** 演示模式，**When** 请求写操作，**Then** 不发起真实请求，给出可读提示

---

### User Story 3 - 工具轨迹与结果展示 (Priority: P2)

用户可看到本次回答调用了哪些工具、参数概要、结果状态（成功/失败）与时间；敏感内容脱敏。

**Why this priority**: 提升透明度与可诊断性（用户理解答案来源）。

**Independent Test**: 触发工具调用后，对话中出现工具轨迹条目（名称/参数概要/结果状态）。

**Acceptance Scenarios**:

1. **Given** 发生工具调用，**When** 渲染对话，**Then** 展示工具轨迹（名称 + 参数概要 + 结果状态 + 时间）
2. **Given** 参数或结果含敏感信息（学号/令牌/密钥），**When** 展示轨迹，**Then** 脱敏显示

---

### User Story 4 - 记忆与上下文 (Priority: P2)

agent 构建上下文（学期、当前周次、日期等）以提升回答质量；用户偏好可被"记住"（记忆项写入/读取）。

**Why this priority**: 上下文与记忆让回答更贴合用户（"我这周有什么课"等）。

**Independent Test**: 触发上下文相关提问时结果符合当前学期/周次；"记住偏好"后后续回答可用该偏好。

**Acceptance Scenarios**:

1. **Given** 已登录，**When** agent 构建上下文，**Then** 使用当前学期/周次/日期（对齐既有学期解析）
2. **Given** 用户要求记住某偏好，**When** 调用记忆工具，**Then** 该偏好被记录并在后续会话中可读取

---

### Edge Cases

- provider 不支持工具调用（tools/function calling）时：给出可读提示或降级为纯文本对话（不崩溃）
- 单轮工具调用过多/无限循环：受**最大轮数**约束，超出后停止并汇总
- 工具参数缺失/非法：**不执行**写操作，返回可读校验错误回灌模型
- 写操作预览与执行之间状态变化（如座位已被占）：执行失败须回灌可读错误（可重试）
- 未登录/会话失效：只读工具走既有会话恢复；不可恢复时给出可读提示
- 演示模式：agent 不发起真实网络/写操作，返回模拟结果
- 敏感信息（API Key、令牌、学号）不得出现在日志或可见轨迹明文
- 不可逆写工具（选课/退课）：本期**不注册**（模型不可调用）；若模型臆造该工具，须拒绝并提示

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 必须实现 agent 循环：模型可返回工具调用 → 系统执行 → 结果回灌模型 → 直至产出最终回复；循环受**最大工具轮数**上限约束
- **FR-002**: 必须提供**工具注册表**：只读 38 + 可逆写 11；每个工具含名称、描述、参数 schema、权限、风险等级与执行实现（对照原项目语义）
- **FR-003**: 只读工具必须直接执行并回灌结果（不改动任何数据）
- **FR-004**: 可逆写工具必须遵循"dry-run 预览 → 用户二次确认 → 执行 → 执行后验证"；**未确认不得执行**
- **FR-005**: 不可逆写工具（选课/退课）本期**不得注册/不得执行**；模型请求时明确拒绝并提示
- **FR-006**: 工具执行异常必须转为可读结果回灌模型，不中断对话
- **FR-007**: 必须记录并可展示**工具轨迹**（调用/参数概要/结果状态/时间）；敏感信息脱敏
- **FR-008**: 必须构建 **AgentContext**（学期/周次/日期等）并支持**记忆项**（写入/读取，用于"记住偏好"）
- **FR-009**: 必须复用既有 provider 配置与流式聊天；LLM 请求须按所配 provider 的工具调用格式发起（OpenAI-compatible tools）
- **FR-010**: 演示模式下 agent 不得发起真实网络或写操作，须返回模拟结果
- **FR-011**: 必须记录**审计**（工具、参数概要、结果、时间、风险等级），供会话内查询
- **FR-012**: 工具参数在进入写操作前必须**校验**；校验失败不得执行并返回可读原因
- **FR-013**: 布局与文案遵循项目约定（全宽卡片配 `constraintSize` 防右缘溢出）；新增可见文案走 i18n（中/英成对）
- **FR-014**: 日志与可见轨迹 MUST NOT 包含 API Key、令牌、完整学号等敏感明文
- **FR-015**: agent 必须逐轮**流式**请求模型；**最终回答必须流式增量渲染**（边生成边显示）；中间工具调用轮次不产生可见正文（用户变更：输出改为流式）

### Key Entities *(include if feature involves data)*

- **工具定义（ToolDefinition）**：名称、描述、参数 schema、权限、风险等级（只读/可逆写/不可逆写）、执行入口
- **工具调用（ToolCall）**：调用 id、工具名、参数（JSON 文本）
- **工具结果（ToolResult）**：调用 id、内容（文本）
- **操作预览（ActionPreview）**：标题、摘要、受影响资源、是否可逆
- **确认规格（ConfirmationSpec）**：确认标题/提示、是否必需
- **审计记录（AuditRecord）**：工具、参数概要、结果、时间、风险等级
- **工具轨迹（ToolTrace）**：调用 id、名称、参数、结果、时间、成功与否
- **Agent 上下文（AgentContext）**：学号、学期名、日期、当前周次
- **记忆项（AIMemory）**：键、值、更新时间
- **会话/消息（Conversation/ChatMessage）**：沿用既有（消息可携带工具调用与结果）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 只读问答在工具可用时，**≥90%** 的请求能调用正确工具并给出基于真实数据的答案
- **SC-002**: 每个可逆写操作**100% 经过二次确认**，未确认执行率 = 0
- **SC-003**: 可逆写执行后**100% 进行执行后验证**并写入审计
- **SC-004**: 不可逆写工具被调用的执行次数 = 0（本期）
- **SC-005**: 工具执行失败时**100%** 以可读结果回灌并保持会话可继续（无崩溃）
- **SC-006**: 演示模式下真实网络/写请求数 = 0
- **SC-007**: 日志与可见轨迹中敏感明文出现次数 = 0
- **SC-008**: agent 循环在达到最大轮数时**100% 能正常收敛**（不无限循环）
- **SC-009**: 最终回答在生成过程中**可见增量输出**（流式渲染），且工具调用轮次不产生可见正文

## Assumptions

- 复用既有 provider 配置（`LLMService`/`ApiKeyStore`）与流式聊天；本特性需扩展 `LLMService` 支持工具调用（tools/function calling）
- 工具基于既有校园服务实现（如空教室/成绩/电费/洗衣机/校园卡/校园网/体育/图书馆座位与研读间等）；**若某工具所需的底层能力在 Harmony 尚未具备，须随本特性补齐或将该工具延后**（见 Open Questions）
- 写操作语义对齐原项目：dry-run 预览、`requiresConfirmation`、执行后 verify、审计
- 领域类型沿用既有 `AIAgentTypes`/`ActionTypes`/`AgentUITypes`
- 不可逆写（选课/退课）本期不接入
- 审计范围默认为**会话内**（是否持久化见 Open Questions）

## Open Questions

- 所配 provider 是否支持 OpenAI-compatible 工具调用；若不支持，降级策略（提示 / 纯文本）如何取舍
- 以下写工具的底层能力在 Harmony 是否已具备、是否随本特性补齐：`recharge_campus_card`、`add/remove_personal_event`、`add/remove_manual_deadline`
- 审计是否需要跨会话持久化
