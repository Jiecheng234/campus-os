## Phase 4: 基础设施与核心服务

### 4.1 加密与编码工具层

**目标**：将原项目 `src/polyfills.ts` + `crypto-js` + `sm-crypto` 迁移为 ArkTS 原生实现。

| 工具 | ArkTS 方案 | 参考原始文件 |
|------|-----------|-------------|
| Base64 编解码 | `util.Base64Helper` | `src/polyfills.ts` |
| SM2 加密/SM3 哈希/SM4 加解密 | `@ohos.security.cryptoFramework` 或纯 JS `sm-crypto` 端口 | `src/services/auth/sm2.ts` |
| AES-256 加密 | `cryptoFramework.createCipher('AES256|GCM|PKCS7')` | HUKS TurboModule 已有 |
| SHA-256/MD5 哈希 | `cryptoFramework.createMac` | 多处使用 |
| UUID v4 生成 | `util.generateRandomUUID()` | `src/services/auth/tsinghuaAuth.ts` |
| GBK ↔ UTF-8 编码 | 自建 GBK 解码器（campus 系统用 GBK） | `src/utils/encoding.ts` |
| Buffer | `util.buffer` 或 `ArrayBuffer` 替代 | `src/polyfills.ts` |
| 随机数 | `cryptoFramework.createRandom` | `react-native-get-random-values` 替代 |

**新建文件**：
- `[utils/CryptoUtils.ets](harmony/entry/src/main/ets/utils/CryptoUtils.ets)` — Base64, MD5, SHA256, UUID, GBK
- `[utils/SM2Crypto.ets](harmony/entry/src/main/ets/utils/SM2Crypto.ets)` — SM2 密钥提取 + 加密
- `[utils/EncodingUtils.ets](harmony/entry/src/main/ets/utils/EncodingUtils.ets)` — GBK ↔ UTF-8

### 4.2 HTTP 客户端与 WebVPN 传输层

### 4.4 状态管理架构

**目标**：建立 ArkTS 原生状态管理层，替代 Redux（6 slices + thunks + selectors）。

**方案**：不引入 Redux（纯 JS 库需 RN 运行时），采用 ArkTS 原生方案：

```
AppStorage (全局单例)
├── @StorageLink/@StorageProp (UI 组件绑定)
├── StateManager 类 (业务逻辑层状态容器)
│   ├── AuthManager
│   ├── LearningManager
│   ├── ScheduleManager
│   ├── AIChatManager
│   └── SettingsManager
└── PersistentState (自动同步到 preferences)
```

| Redux Slice | ArkTS 等价 |
|-------------|-----------|
| `authSlice` | `AuthManager` → `AppStorage` 中的 `authState` |
| `learningSlice` | `LearningManager` → `AppStorage` 中的 `learningData` |
| `scheduleSlice` | `ScheduleManager` → `AppStorage` 中的 `scheduleData` |
| `manualDeadlineSlice` | 合入 `LearningManager` |
| `aiSlice` | `AIChatManager` → `AppStorage` 中的 `aiChatState` |
| `settingsSlice` | `SettingsManager` → `AppStorage` 中的 `settings` |

**Selectors** 通过 Manager 类的方法实现（如 `LearningManager.getTodayCourses()`）。

**新建文件**：
- `[state/StateManager.ets](harmony/entry/src/main/ets/state/StateManager.ets)` — 全局管理器注册与初始化

## Phase 5: 认证系统

### 目标

实现真实的清华大学统一身份认证，替换当前的 Mock 登录。

### 5.1 核心认证流程

基于 `src/services/auth/tsinghuaAuth.ts`（927 行），在 ArkTS 中复现以下流程：

```
1. 清除 Cookie → 
2. GET WebVPN OAuth URL (提取 CSRF token + SM2 public key) →
3. 用 SM2 公钥加密密码 →
4. POST 登录表单 (学号 + 加密密码 + CSRF token) →
5. 解析响应 → 
   ├── 成功 → 提取 WebVPN Cookie → roam 子系统 (info/learn/id)
   └── 需要2FA → 提取2FA选项 (微信/短信/TOTP) →
        6. 发送验证码请求 →
        7. POST 2FA 验证 →
        8. 成功后 roam 子系统
```

### 5.2 2FA 支持

| 方式 | 实现 |
|------|------|
| 微信 | 调用微信小程序/绑定通知 → 轮询验证 |
| 短信 | POST 发送验证码请求 → 用户输入 → POST 验证 |
| TOTP | 基于时间的一次性密码 → POST 验证 |

### 5.3 Demo 模式保留

- `AuthManager.demoMode: boolean`
- Demo 模式跳过 SM2 + WebVPN 链，直接加载预设 Mock 数据
- 在 `SettingsPage` 中可切换

### 5.4 新建/修改文件

| `state/AuthManager.ets` | 新增 | 认证状态机 + 方法 |

## 风险与兼容性

| 风险 | 等级 | 缓解措施 |
|------|------|---------|
| SM2 加密在 ArkTS 中实现复杂 | 🔴 高 | 优先尝试 `cryptoFramework` 原生支持；若不支持 SM2 曲线则 port 纯 JS `sm-crypto` |
| WebVPN 系统反爬机制变化 | 🟡 中 | 在 Phase 5 中预留足够的调试日志和错误处理，参考原始 TS 代码 |
| AI 流式解析在 ArkTS 中性能 | 🟡 中 | 使用 `TaskPool` 后台解析，UI 分批更新 |
| GBK 编码无原生支持 | 🟡 中 | 自建 GBK 解码表（常见字符集覆盖 campus 系统） |
| ArkTS 不支持 `any`/`dynamic` | 🟢 低 | 所有接口已定义，在 Phase 4 完善类型系统 |
| 平板布局复杂度 | 🟢 低 | `BreakpointSystem` 渐进式适配 |
